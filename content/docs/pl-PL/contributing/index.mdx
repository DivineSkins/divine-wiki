Każdy może dołożyć coś do tej wiki. Każdy poradnik to plik tekstowy trzymany na GitHubie, darmowej stronie, na której ludzie wspólnie pracują nad plikami. Ty proponujesz zmianę. Opiekun ją sprawdza i publikuje.

## Zanim zaczniesz

Potrzebujesz darmowego konta GitHub. Załóż je na [github.com/signup](https://github.com/signup). To jedyna konfiguracja.

Trzy słowa, które będziesz często widzieć:

- **Fork** to twoja własna kopia plików wiki na GitHubie.
- **Commit** to zapisana zmiana w tych plikach.
- **Pull request** (albo **PR**) prosi opiekunów o opublikowanie twojej zmiany.

## Napisz nowy poradnik

Wiki ma edytor wizualny. Piszesz w przeglądarce i widzisz podgląd na żywo. Bez pobierania, bez kodu.

{/* Screenshot: the Contribute picker with the Visual editor and Manual on GitHub cards */}

1. Kliknij **Contribute** na górnym pasku. Otworzy się okno z dwiema opcjami.
2. Wybierz **Visual editor**. Edytor się otworzy.
3. Wypełnij **Title**, **Category** i **Description**.
4. Pisz poradnik po lewej. Prawa strona pokazuje, jak będzie wyglądać opublikowana strona.

{/* Screenshot: the draft editor with the live preview on the right */}

<Callout type="info" title="Wskazówki do edytora">
  Pasek narzędzi wrzuca gotowe komponenty, jak callouty i osadzone filmy. Wpisz
  `@`, żeby podlinkować inny poradnik. Wszystko, czego możesz użyć, znajdziesz na
  [stronie komponentów](/docs/lol/contributing/components).
</Callout>

Gotowy, żeby to wysłać?

5. Kliknij **Contribute** w prawym górnym rogu.
6. Edytor może zaproponować linki do innych poradników, które znalazł w twoim tekście. Kliknij te, które chcesz, potem kliknij **Continue to GitHub**.
7. Otworzy się okno **Publish your guide**. Ma trzy kroki. Trzymaj tę kartę otwartą, aż skończysz.
8. Wpisz swoją nazwę użytkownika GitHub w polu. Przyciski poniżej używają jej, żeby znaleźć twojego forka.
9. Kliknij **Fork on GitHub**. GitHub otworzy stronę **Create a new fork**. Kliknij zielony przycisk **Create fork**. To tworzy twoją własną kopię wiki. Robisz to tylko raz. Masz już forka? Pomiń ten krok.

   <img
     src="/wiki-images/contribute-create-fork.webp"
     alt="Strona Create a new fork na GitHubie. Strzałka wskazuje zielony przycisk Create fork w prawym dolnym rogu."
   />

10. Wróć do karty z wiki. Kliknij **Create the file on GitHub**.

    <img
      src="/wiki-images/contribute-step-create-file.webp"
      alt="Okno Publish your guide. Strzałka wskazuje przycisk Create the file on GitHub w kroku 2."
    />

11. GitHub otworzy nowy plik w twoim forku z wypełnionym poradnikiem. Sprawdź nazwę pliku i tekst. Potem kliknij zielony przycisk **Commit changes...** w prawym górnym rogu.

    <img
      src="/wiki-images/contribute-verify-file.webp"
      alt="Edytor nowego pliku na GitHubie z wypełnionym poradnikiem. Pole z nazwą pliku jest wyróżnione z notatką, żeby sprawdzić zawartość i nazwę, a strzałka wskazuje przycisk Commit changes."
    />

12. Otworzy się małe okno. Zostaw pierwszą opcję, **Commit directly to the main branch**. Kliknij **Commit changes**.

    <img
      src="/wiki-images/contribute-commit-changes.webp"
      alt="Okno Commit changes na GitHubie. Zaznaczona jest opcja Commit directly to the main branch, a strzałka wskazuje zielony przycisk Commit changes."
    />

13. Wróć do karty z wiki. Kliknij **Open the pull request on GitHub**.

    <img
      src="/wiki-images/contribute-step-open-pr.webp"
      alt="Okno Publish your guide. Strzałka wskazuje przycisk Open the pull request on GitHub w kroku 3."
    />

14. GitHub pokaże twoje zmiany i formularz. Wypełnij formularz. Zostaw zaznaczone **Allow edits by maintainers**. Kliknij **Create pull request**.

    <img
      src="/wiki-images/contribute-create-pull-request.webp"
      alt="Strona Open a pull request na GitHubie z formularzem pull requesta wiki. Strzałka wskazuje zielony przycisk Create pull request."
    />

To wszystko. Opiekun sprawdza twój poradnik i publikuje go. Twój poradnik używał obrazków? Jeszcze jeden krok: zobacz [Dodaj obrazki](#dodaj-obrazki) poniżej.

<Callout type="info">
  Długi draft? GitHub nie potrafi wstępnie wypełnić bardzo długich plików. Krok 2
  pokaże wtedy przycisk **Copy MDX**. Skopiuj swój draft, potem wklej go do
  pustego pliku, który otworzy GitHub.
</Callout>

## Edytuj istniejący poradnik

1. Otwórz poradnik, który chcesz zmienić.
2. Zjedź na sam dół. Kliknij **Edit on GitHub**. Edytor wizualny otworzy się z wczytanym poradnikiem.
3. Wprowadź zmiany.
4. Kliknij **Contribute**.
5. Kliknij **Copy MDX**. GitHub nie potrafi wstępnie wypełnić edycji, więc wklejasz je sam.
6. Kliknij **Open guide on GitHub**.
7. Kliknij ikonę ołówka w prawym górnym rogu pliku.
8. Zaznacz cały stary tekst. Wklej na niego swoją kopię.
9. Kliknij **Commit changes...**, potem **Propose changes**, potem **Create pull request**.

## Dodaj obrazki

W edytorze kliknij **Upload image**, żeby wstawić obrazek do poradnika. Obrazek od razu pojawia się w podglądzie. Ale plik obrazka nie jedzie na GitHuba razem z tekstem. Wgrywasz go sam, po zacommitowaniu poradnika.

### Wgraj obrazki po zacommitowaniu

Kiedy twój draft używa obrazków, okno Contribute wypisuje dokładne nazwy plików do wgrania. Miej tę listę pod ręką.

<img
  src="/wiki-images/contribute-upload-images-reminder.webp"
  alt="Okno Publish your guide z wyróżnioną kartą One more step: upload your images. Wypisuje plik obrazka do wgrania i przycisk Upload on GitHub."
/>

1. Najpierw zacommituj poradnik (kroki powyżej), żeby twój pull request istniał.
2. Wróć do karty z wiki. W oknie Contribute kliknij **Upload on GitHub**. Otworzy się folder z obrazkami twojego forka.
3. Przeciągnij do niego obrazki. Zachowaj nazwy plików dokładnie takie, jakich używa twój poradnik.
4. Kliknij **Commit changes**. Zostaw pierwszą opcję, commit do main.

{/* Screenshot: GitHub's Upload files page inside public/wiki-images */}

Obrazki same dołączają do twojego pull requesta. Pokazują się na wiki, gdy twój pull request zostanie zmergowany.

<Callout type="info">
  Edytowałeś istniejący poradnik? GitHub umieścił twoją zmianę na branchu z nazwą
  w stylu `patch-1`. Otwórz swój pull request, kliknij tę nazwę brancha u góry,
  otwórz `public/wiki-images`, potem kliknij **Add file** i **Upload files**.
  Zacommituj do tego samego brancha.
</Callout>

### Zasady dla obrazków

- Używaj małych liter w nazwach plików z myślnikami: `moj-screenshot.png`, nie `Moj Screenshot.png`.
- Daj każdemu obrazkowi alt text, który go opisuje. Opiekunowie to sprawdzają.
- Trzymaj każdy plik poniżej 500 KB. Większe pliki spowalniają stronę.
- Używaj PNG do screenshotów, JPG do zdjęć. WebP też działa.

## Co się dzieje po otwarciu pull requesta

1. Jako komentarz do twojego pull requesta pojawia się link do podglądu. Otwórz go, żeby zobaczyć swoją zmianę na żywo.
2. Opiekun sprawdza twój tekst, linki i obrazki. Może poprosić o drobne zmiany.
3. Po zatwierdzeniu twoja zmiana zostaje zmergowana. Wchodzi na wiki w ciągu kilku minut.

## Pracuj na swoim komputerze (zaawansowane)

Przy nowych kategoriach, dużych przeróbkach albo wielu plikach naraz pracuj lokalnie. Potrzebujesz Node 22+, Gita i edytora kodu.

```bash
git clone https://github.com/<your-username>/divine-wiki.git
cd divine-wiki
npm install
npm run dev
```

Najpierw zforkuj repo na [github.com/DivineSkins/divine-wiki](https://github.com/DivineSkins/divine-wiki), potem sklonuj swojego forka. Otwórz `http://localhost:3000`, żeby sprawdzić, czy strona się wczytuje. Zrób brancha, zmieniaj pliki w `content/docs/en/lol/`, wrzucaj obrazki do `public/wiki-images/`, potem zrób push i otwórz pull request do `main`.
