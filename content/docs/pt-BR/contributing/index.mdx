Qualquer pessoa pode adicionar conteúdo a este wiki. Cada guia é um arquivo de texto armazenado no GitHub, um site gratuito onde pessoas trabalham juntas em arquivos. Você sugere uma alteração. Um mantenedor revisa e publica.

## Antes de começar

Você precisa de uma conta gratuita no GitHub. Crie uma em [github.com/signup](https://github.com/signup). Esse é o único passo de configuração.

Três palavras que você verá muito:

- Um **fork** é sua própria cópia dos arquivos do wiki no GitHub.
- Um **commit** é uma alteração salva nesses arquivos.
- Um **pull request** (ou **PR**) é um pedido para que os mantenedores publiquem sua alteração.

## Escreva um novo guia

O wiki tem um editor visual. Você escreve no navegador e vê uma pré-visualização ao vivo. Sem downloads, sem código.

{/* Screenshot: o seletor Contribute com os cartões Visual editor e Manual on GitHub */}

1. Clique em **Contribute** na barra superior. Uma janela com duas opções abre.
2. Escolha **Visual editor**. O editor será aberto.
3. Preencha **Title**, **Category** e **Description**.
4. Escreva seu guia à esquerda. O lado direito mostra como a página publicada ficará.

{/* Screenshot: o editor de rascunho com a pré-visualização ao vivo à direita */}

<Callout type="info" title="Dicas do editor">
  A barra de ferramentas insere componentes prontos como callouts e vídeos
  embutidos. Digite `@` para linkar outro guia. Veja a [página de
  componentes](/docs/lol/contributing/components) para tudo que você pode usar.
</Callout>

Pronto para enviar?

5. Clique em **Contribute** no canto superior direito.
6. O editor pode sugerir links para outros guias que ele encontrou no seu texto. Clique nos que você quiser e depois clique em **Continue to GitHub**.
7. A janela **Publish your guide** abre. Ela tem três etapas. Mantenha esta aba aberta até terminar.
8. Digite seu usuário do GitHub na caixa. Os botões abaixo usam isso para encontrar seu fork.
9. Clique em **Fork on GitHub**. O GitHub abre a página **Create a new fork**. Clique no botão verde **Create fork**. Isso cria sua própria cópia do wiki. Você só faz isso uma vez. Já tem um fork? Pule esta etapa.

   <img
     src="/wiki-images/contribute-create-fork.webp"
     alt="A página Create a new fork do GitHub. Uma seta aponta para o botão verde Create fork no canto inferior direito."
   />

10. Volte para a aba do wiki. Clique em **Create the file on GitHub**.

    <img
      src="/wiki-images/contribute-step-create-file.webp"
      alt="A janela Publish your guide. Uma seta aponta para o botão Create the file on GitHub abaixo da etapa 2."
    />

11. O GitHub abre um novo arquivo no seu fork com seu guia preenchido. Confira o nome do arquivo e o texto. Depois clique no botão verde **Commit changes...** no canto superior direito.

    <img
      src="/wiki-images/contribute-verify-file.webp"
      alt="O editor de novo arquivo do GitHub com o guia preenchido. O campo do nome do arquivo está destacado com a nota para verificar o conteúdo e o nome, e uma seta aponta para o botão Commit changes."
    />

12. Uma pequena janela abre. Mantenha a primeira opção, **Commit directly to the main branch**. Clique em **Commit changes**.

    <img
      src="/wiki-images/contribute-commit-changes.webp"
      alt="A janela Commit changes do GitHub. A opção Commit directly to the main branch está selecionada e uma seta aponta para o botão verde Commit changes."
    />

13. Volte para a aba do wiki. Clique em **Open the pull request on GitHub**.

    <img
      src="/wiki-images/contribute-step-open-pr.webp"
      alt="A janela Publish your guide. Uma seta aponta para o botão Open the pull request on GitHub abaixo da etapa 3."
    />

14. O GitHub mostra suas alterações e um formulário. Preencha o formulário. Deixe **Allow edits by maintainers** marcado. Clique em **Create pull request**.

    <img
      src="/wiki-images/contribute-create-pull-request.webp"
      alt="A página Open a pull request do GitHub com o formulário de pull request do wiki. Uma seta aponta para o botão verde Create pull request."
    />

Pronto. Um mantenedor revisa seu guia e publica. Seu guia usou imagens? Falta mais um passo: veja [Adicionar imagens](#adicionar-imagens) abaixo.

<Callout type="info">
  Rascunho longo? O GitHub não consegue preencher arquivos muito grandes. A
  etapa 2 mostra um botão **Copy MDX** no lugar. Copie seu rascunho e cole no
  arquivo vazio que o GitHub abre.
</Callout>

## Editar um guia existente

1. Abra o guia que você quer alterar.
2. Role até o final. Clique em **Edit on GitHub**. O editor visual abre com o guia carregado.
3. Faça suas alterações.
4. Clique em **Contribute**.
5. Clique em **Copy MDX**. O GitHub não consegue preencher edições, então você mesmo cola o texto.
6. Clique em **Open guide on GitHub**.
7. Clique no ícone de lápis no canto superior direito do arquivo.
8. Selecione todo o texto antigo. Cole sua cópia por cima.
9. Clique em **Commit changes...**, depois em **Propose changes** e por fim em **Create pull request**.

## Adicionar imagens

No editor, clique em **Upload image** para colocar uma imagem no seu guia. A imagem aparece na sua pré-visualização na hora. Mas o arquivo de imagem não vai junto com seu texto para o GitHub. Você mesmo o envia, depois de fazer o commit do guia.

### Envie suas imagens depois do commit

Quando seu rascunho usa imagens, a janela Contribute lista os nomes exatos dos arquivos para enviar. Mantenha essa lista à mão.

<img
  src="/wiki-images/contribute-upload-images-reminder.webp"
  alt="A janela Publish your guide com o cartão One more step: upload your images destacado. Ele lista o arquivo de imagem a enviar e um botão Upload on GitHub."
/>

1. Faça o commit do seu guia primeiro (os passos acima), para que seu pull request exista.
2. Volte para a aba do wiki. Na janela Contribute, clique em **Upload on GitHub**. A pasta de imagens do seu fork abre.
3. Arraste suas imagens para dentro. Mantenha os nomes dos arquivos exatamente como seu guia usa.
4. Clique em **Commit changes**. Mantenha a primeira opção, commit na main.

{/* Screenshot: a página Upload files do GitHub dentro de public/wiki-images */}

As imagens entram no seu pull request sozinhas. Elas aparecem no wiki assim que seu pull request for mesclado.

<Callout type="info">
  Editou um guia existente em vez disso? O GitHub colocou sua alteração em um
  branch com nome parecido com `patch-1`. Abra seu pull request, clique no nome
  desse branch perto do topo, abra `public/wiki-images`, depois clique em **Add
  file** e **Upload files**. Faça o commit no mesmo branch.
</Callout>

### Regras de imagem

- Use nomes de arquivo em minúsculas com traços: `minha-captura.png`, não `Minha Captura.png`.
- Dê a cada imagem um alt text que a descreva. Os revisores verificam isso.
- Mantenha cada arquivo abaixo de 500 KB. Arquivos maiores deixam o site lento.
- Use PNG para capturas de tela, JPG para fotos. WebP também funciona.

## O que acontece depois que você abre um pull request

1. Um link de pré-visualização aparece como comentário no seu pull request. Abra para ver sua alteração ao vivo.
2. Um mantenedor revisa seu texto, links e imagens. Ele pode pedir pequenas alterações.
3. Depois de aprovada, sua alteração é mesclada. Ela vai ao ar no wiki em poucos minutos.

## Trabalhe no seu computador (avançado)

Para novas categorias, grandes reescritas ou muitos arquivos de uma vez, trabalhe localmente. Você precisa do Node 22+, do Git e de um editor de código.

```bash
git clone https://github.com/<seu-usuario>/divine-wiki.git
cd divine-wiki
npm install
npm run dev
```

Primeiro, faça um fork do repositório em [github.com/DivineSkins/divine-wiki](https://github.com/DivineSkins/divine-wiki) e então clone o seu fork. Abra `http://localhost:3000` para verificar se o site carrega. Crie um branch, altere os arquivos em `content/docs/en/lol/`, coloque as imagens em `public/wiki-images/`, e então faça push e abra um pull request para `main`.

## Precisa de ajuda?

- Travou no GitHub ou no editor? Pergunte em `#wiki-feedback` no Discord.
- Planejando uma grande alteração, como uma nova categoria ou uma reestruturação? Poste em `#wiki-proposals` primeiro. Isso evita que você faça um trabalho que acaba sendo rejeitado.
