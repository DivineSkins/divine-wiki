Tout le monde peut enrichir ce wiki. Chaque guide est un fichier texte stocké sur GitHub, un site gratuit où les gens travaillent ensemble sur des fichiers. Tu proposes une modification. Un mainteneur la vérifie et la publie.

## Avant de commencer

Il te faut un compte GitHub gratuit. Crée-en un sur [github.com/signup](https://github.com/signup). C'est la seule préparation.

Trois mots que tu vas voir souvent :

- Un **fork** est ta propre copie des fichiers du wiki sur GitHub.
- Un **commit** est une modification enregistrée de ces fichiers.
- Une **pull request** (ou **PR**) demande aux mainteneurs de publier ta modification.

## Écrire un nouveau guide

Le wiki a un éditeur visuel. Tu écris dans le navigateur et tu vois un aperçu en direct. Aucun téléchargement, aucun code.

{/* Screenshot: the Contribute picker with the Visual editor and Manual on GitHub cards */}

1. Clique sur **Contribute** dans la barre du haut. Une fenêtre avec deux options s'ouvre.
2. Choisis **Visual editor**. L'éditeur s'ouvre.
3. Remplis **Title**, **Category** et **Description**.
4. Écris ton guide à gauche. À droite, tu vois à quoi ressemblera la page publiée.

{/* Screenshot: the draft editor with the live preview on the right */}

<Callout type="info" title="Astuces de l'éditeur">
  La barre d'outils insère des composants prêts à l'emploi comme les callouts et
  les vidéos intégrées. Tape `@` pour lier vers un autre guide. Consulte la [page
  des composants](/docs/lol/contributing/components) pour tout ce que tu peux
  utiliser.
</Callout>

Prêt à l'envoyer ?

5. Clique sur **Contribute** en haut à droite.
6. L'éditeur peut te proposer des liens vers d'autres guides trouvés dans ton texte. Clique sur ceux que tu veux, puis clique sur **Continue to GitHub**.
7. La fenêtre **Publish your guide** s'ouvre. Elle a trois étapes. Garde cet onglet ouvert jusqu'à la fin.
8. Tape ton nom d'utilisateur GitHub dans le champ. Les boutons en dessous s'en servent pour trouver ton fork.
9. Clique sur **Fork on GitHub**. GitHub ouvre la page **Create a new fork**. Clique sur le bouton vert **Create fork**. Ça crée ta propre copie du wiki. Tu ne le fais qu'une fois. Tu as déjà un fork ? Passe cette étape.

   <img
     src="/wiki-images/contribute-create-fork.png"
     alt="La page Create a new fork de GitHub. Une flèche pointe vers le bouton vert Create fork en bas à droite."
   />

10. Reviens sur l'onglet du wiki. Clique sur **Create the file on GitHub**.

    <img
      src="/wiki-images/contribute-step-create-file.jpg"
      alt="La fenêtre Publish your guide. Une flèche pointe vers le bouton Create the file on GitHub sous l'étape 2."
    />

11. GitHub ouvre un nouveau fichier sur ton fork avec ton guide déjà rempli. Vérifie le nom du fichier et le texte. Puis clique sur le bouton vert **Commit changes...** en haut à droite.

    <img
      src="/wiki-images/contribute-verify-file.png"
      alt="L'éditeur de nouveau fichier de GitHub avec le guide rempli. Le champ du nom de fichier est mis en évidence avec la note de vérifier le contenu et le nom, et une flèche pointe vers le bouton Commit changes."
    />

12. Une petite fenêtre s'ouvre. Garde la première option, **Commit directly to the main branch**. Clique sur **Commit changes**.

    <img
      src="/wiki-images/contribute-commit-changes.png"
      alt="La fenêtre Commit changes de GitHub. Commit directly to the main branch est sélectionné et une flèche pointe vers le bouton vert Commit changes."
    />

13. Reviens sur l'onglet du wiki. Clique sur **Open the pull request on GitHub**.

    <img
      src="/wiki-images/contribute-step-open-pr.jpg"
      alt="La fenêtre Publish your guide. Une flèche pointe vers le bouton Open the pull request on GitHub sous l'étape 3."
    />

14. GitHub affiche tes modifications et un formulaire. Remplis le formulaire. Laisse **Allow edits by maintainers** coché. Clique sur **Create pull request**.

    <img
      src="/wiki-images/contribute-create-pull-request.png"
      alt="La page Open a pull request de GitHub avec le formulaire de pull request du wiki. Une flèche pointe vers le bouton vert Create pull request."
    />

C'est tout. Un mainteneur relit ton guide et le publie. Ton guide utilise des images ? Une étape en plus : va voir [Ajouter des images](#add-images) plus bas.

<Callout type="info">
  Brouillon long ? GitHub ne peut pas pré-remplir les fichiers très longs.
  L'étape 2 affiche alors un bouton **Copy MDX**. Copie ton brouillon, puis
  colle-le dans le fichier vide que GitHub ouvre.
</Callout>

## Modifier un guide existant

1. Ouvre le guide que tu veux changer.
2. Descends tout en bas. Clique sur **Edit on GitHub**. L'éditeur visuel s'ouvre avec le guide chargé.
3. Fais tes modifications.
4. Clique sur **Contribute**.
5. Clique sur **Copy MDX**. GitHub ne peut pas pré-remplir les modifications, donc tu les colles toi-même.
6. Clique sur **Open guide on GitHub**.
7. Clique sur l'icône du crayon en haut à droite du fichier.
8. Sélectionne tout l'ancien texte. Colle ta copie par-dessus.
9. Clique sur **Commit changes...**, puis **Propose changes**, puis **Create pull request**.

## Ajouter des images

Dans l'éditeur, clique sur **Upload image** pour mettre une image dans ton guide. L'image apparaît tout de suite dans ton aperçu. Mais le fichier image ne part pas vers GitHub avec ton texte. Tu l'envoies toi-même, après avoir commité le guide.

### Envoie tes images après le commit

Quand ton brouillon utilise des images, la fenêtre Contribute liste les noms de fichiers exacts à envoyer. Garde cette liste sous la main.

<img
  src="/wiki-images/contribute-upload-images-reminder.jpg"
  alt="La fenêtre Publish your guide avec la carte One more step: upload your images mise en évidence. Elle liste le fichier image à envoyer et un bouton Upload on GitHub."
/>

1. Commite ton guide d'abord (les étapes ci-dessus), pour que ta pull request existe.
2. Reviens sur l'onglet du wiki. Dans la fenêtre Contribute, clique sur **Upload on GitHub**. Le dossier d'images de ton fork s'ouvre.
3. Glisse tes images dedans. Garde les noms de fichiers exactement comme ton guide les utilise.
4. Clique sur **Commit changes**. Garde la première option, commit vers main.

{/* Screenshot: GitHub's Upload files page inside public/wiki-images */}

Les images rejoignent ta pull request toutes seules. Elles s'affichent sur le wiki une fois ta pull request fusionnée.

<Callout type="info">
  Tu as modifié un guide existant à la place ? GitHub a mis ta modification sur
  une branche avec un nom comme `patch-1`. Ouvre ta pull request, clique sur ce
  nom de branche près du haut, ouvre `public/wiki-images`, puis clique sur **Add
  file** et **Upload files**. Commite sur la même branche.
</Callout>

### Règles pour les images

- Utilise des noms de fichiers en minuscules avec des tirets : `my-screenshot.png`, pas `My Screenshot.png`.
- Donne à chaque image un texte alt qui la décrit. Les relecteurs le vérifient.
- Garde chaque fichier sous 500 Ko. Les fichiers plus lourds ralentissent le site.
- Utilise le PNG pour les captures d'écran, le JPG pour les photos. Le WebP marche aussi.

## Ce qui se passe après l'ouverture d'une pull request

1. Un lien d'aperçu apparaît en commentaire sur ta pull request. Ouvre-le pour voir ta modification en direct.
2. Un mainteneur relit ton texte, tes liens et tes images. Il peut demander de petites modifications.
3. Une fois approuvée, ta modification est fusionnée. Elle passe en ligne sur le wiki en quelques minutes.

## Travailler sur ton ordinateur (avancé)

Pour de nouvelles catégories, de grosses réécritures ou plusieurs fichiers à la fois, travaille en local. Il te faut Node 22+, Git et un éditeur de code.

```bash
git clone https://github.com/<your-username>/divine-wiki.git
cd divine-wiki
npm install
npm run dev
```

Forke d'abord le dépôt sur [github.com/DivineSkins/divine-wiki](https://github.com/DivineSkins/divine-wiki), puis clone ton fork. Ouvre `http://localhost:3000` pour vérifier que le site se charge. Crée une branche, modifie les fichiers dans `content/docs/en/lol/`, dépose des images dans `public/wiki-images/`, puis pousse et ouvre une pull request vers `main`.

## Besoin d'aide ?

- Bloqué sur GitHub ou l'éditeur ? Demande dans `#wiki-feedback` sur Discord.
- Tu prépares un gros changement, comme une nouvelle catégorie ou une restructuration ? Poste d'abord dans `#wiki-proposals`. Ça t'évite de faire un travail qui se fait rejeter.
