Bu wiki'ye herkes ekleme yapabilir. Her rehber, insanların dosyalar üzerinde birlikte çalıştığı ücretsiz bir site olan GitHub'da tutulan bir metin dosyası. Sen bir değişiklik önerirsin. Bir wiki sorumlusu onu kontrol edip yayınlar.

## Başlamadan önce

Ücretsiz bir GitHub hesabına ihtiyacın var. Bir tane [github.com/signup](https://github.com/signup) adresinden oluştur. Tek kurulum bu.

Sık göreceğin üç kelime:

- **Fork**, wiki'nin dosyalarının GitHub'daki kendi kopyan.
- **Commit**, o dosyalara kaydedilmiş bir değişiklik.
- **Pull request** (ya da **PR**), wiki sorumlularından değişikliğini yayınlamalarını ister.

## Yeni bir rehber yaz

Wiki'nin görsel bir editörü var. Tarayıcıda yazar ve canlı önizleme görürsün. İndirme yok, kod yok.

{/* Screenshot: the Contribute picker with the Visual editor and Manual on GitHub cards */}

1. Üst çubukta **Contribute**'a tıkla. İki seçenekli bir pencere açılır.
2. **Visual editor**'ü seç. Editör açılır.
3. **Title**, **Category** ve **Description** alanlarını doldur.
4. Rehberini solda yaz. Sağ taraf, yayınlanan sayfanın nasıl görüneceğini gösterir.

{/* Screenshot: the draft editor with the live preview on the right */}

<Callout type="info" title="Editör ipuçları">
  Araç çubuğu, callout'lar ve video gömüleri gibi hazır bileşenleri ekler.
  Başka bir rehbere link vermek için `@` yaz. Kullanabileceğin her şey için
  [bileşenler sayfasına](/docs/lol/contributing/components) bak.
</Callout>

Göndermeye hazır mısın?

5. Sağ üstte **Contribute**'a tıkla.
6. Editör, metninde bulduğu başka rehberlere linkler önerebilir. İstediklerine tıkla, sonra **Continue to GitHub**'a tıkla.
7. **Publish your guide** penceresi açılır. Üç adımı var. İşin bitene kadar bu sekmeyi açık tut.
8. GitHub kullanıcı adını kutuya yaz. Aşağıdaki butonlar, fork'unu bulmak için bunu kullanır.
9. **Fork on GitHub**'a tıkla. GitHub, **Create a new fork** sayfasını açar. Yeşil **Create fork** butonuna tıkla. Bu, wiki'nin kendi kopyanı oluşturur. Bunu yalnızca bir kez yaparsın. Zaten bir fork'un mu var? Bu adımı atla.

   <img
     src="/wiki-images/contribute-create-fork.webp"
     alt="GitHub'ın Create a new fork sayfası. Bir ok, sağ alttaki yeşil Create fork butonunu gösteriyor."
   />

10. Wiki sekmesine geri dön. **Create the file on GitHub**'a tıkla.

    <img
      src="/wiki-images/contribute-step-create-file.webp"
      alt="Publish your guide penceresi. Bir ok, 2. adımın altındaki Create the file on GitHub butonunu gösteriyor."
    />

11. GitHub, fork'unda rehberin doldurulmuş halde yeni bir dosya açar. Dosya adını ve metni kontrol et. Sonra sağ üstteki yeşil **Commit changes...** butonuna tıkla.

    <img
      src="/wiki-images/contribute-verify-file.webp"
      alt="GitHub'ın yeni dosya editörü, rehber doldurulmuş halde. Dosya adı alanı, içeriği ve adı doğrulama notuyla vurgulanmış ve bir ok Commit changes butonunu gösteriyor."
    />

12. Küçük bir pencere açılır. İlk seçeneği, **Commit directly to the main branch**'i olduğu gibi bırak. **Commit changes**'e tıkla.

    <img
      src="/wiki-images/contribute-commit-changes.webp"
      alt="GitHub'ın Commit changes penceresi. Commit directly to the main branch seçili ve bir ok yeşil Commit changes butonunu gösteriyor."
    />

13. Wiki sekmesine geri dön. **Open the pull request on GitHub**'a tıkla.

    <img
      src="/wiki-images/contribute-step-open-pr.webp"
      alt="Publish your guide penceresi. Bir ok, 3. adımın altındaki Open the pull request on GitHub butonunu gösteriyor."
    />

14. GitHub, değişikliklerini ve bir form gösterir. Formu doldur. **Allow edits by maintainers** seçeneğini işaretli bırak. **Create pull request**'e tıkla.

    <img
      src="/wiki-images/contribute-create-pull-request.webp"
      alt="GitHub'ın Open a pull request sayfası, wiki'nin pull request formuyla. Bir ok, yeşil Create pull request butonunu gösteriyor."
    />

İşte bu kadar. Bir wiki sorumlusu rehberini inceler ve yayınlar. Rehberin görsel kullandı mı? Bir adım daha var: aşağıdaki [Görselleri ekle](#görselleri-ekle) kısmına bak.

<Callout type="info">
  Uzun bir draft mı? GitHub çok uzun dosyaları önceden dolduramaz. 2. adım bunun
  yerine bir **Copy MDX** butonu gösterir. Draft'ını kopyala, sonra GitHub'ın
  açtığı boş dosyaya yapıştır.
</Callout>

## Var olan bir rehberi düzenle

1. Değiştirmek istediğin rehberi aç.
2. En alta kaydır. **GitHub'da düzenle**'ye tıkla. Görsel editör rehber yüklenmiş halde açılır.
3. Değişikliklerini yap.
4. **Contribute**'a tıkla.
5. **Copy MDX**'e tıkla. GitHub düzenlemeleri önceden dolduramaz, o yüzden onları kendin yapıştırırsın.
6. **Open guide on GitHub**'a tıkla.
7. Dosyanın sağ üstündeki kalem simgesine tıkla.
8. Tüm eski metni seç. Kopyanı üzerine yapıştır.
9. **Commit changes...**, sonra **Propose changes**, sonra **Create pull request**'e tıkla.

## Görselleri ekle

Editörde, rehberine bir resim koymak için **Upload image**'e tıkla. Resim önizlemende hemen görünür. Ama görsel dosyası metninle birlikte GitHub'a gitmez. Onu rehberi commit'ledikten sonra kendin yüklersin.

### Görsellerini commit'ledikten sonra yükle

Draft'ın görsel kullandığında, Contribute penceresi yüklenecek dosya adlarını tam olarak listeler. O listeyi elinin altında tut.

<img
  src="/wiki-images/contribute-upload-images-reminder.webp"
  alt="Publish your guide penceresi, One more step: upload your images kartı vurgulanmış halde. Yüklenecek görsel dosyasını ve bir Upload on GitHub butonunu listeliyor."
/>

1. Pull request'in var olması için önce rehberini commit'le (yukarıdaki adımlar).
2. Wiki sekmesine geri dön. Contribute penceresinde **Upload on GitHub**'a tıkla. Fork'unun görsel klasörü açılır.
3. Görsellerini içine sürükle. Dosya adlarını rehberinin kullandığı gibi birebir koru.
4. **Commit changes**'e tıkla. İlk seçeneği, main'e commit'lemeyi olduğu gibi bırak.

{/* Screenshot: GitHub's Upload files page inside public/wiki-images */}

Görseller pull request'ine kendiliğinden katılır. Pull request'in merge edildiğinde wiki'de görünürler.

<Callout type="info">
  Var olan bir rehberi mi düzenledin? GitHub değişikliğini `patch-1` gibi bir
  adı olan bir branch'e koydu. Pull request'ini aç, üst kısımdaki o branch adına
  tıkla, `public/wiki-images`'i aç, sonra **Add file** ve **Upload files**'a
  tıkla. Aynı branch'e commit'le.
</Callout>

### Görsel kuralları

- Küçük harfli, tireli dosya adları kullan: `My Screenshot.png` değil, `my-screenshot.png`.
- Her görsele onu tanımlayan bir alt text ver. Wiki sorumluları bunu kontrol eder.
- Her dosyayı 500 KB altında tut. Daha büyük dosyalar siteyi yavaşlatır.
- Ekran görüntüleri için PNG, fotoğraflar için JPG kullan. WebP de çalışır.

## Bir pull request açtıktan sonra ne olur

1. Pull request'inde yorum olarak bir önizleme linki görünür. Değişikliğini canlı görmek için onu aç.
2. Bir wiki sorumlusu metnini, linklerini ve görsellerini inceler. Küçük değişiklikler isteyebilir.
3. Onaylandığında değişikliğin merge edilir. Dakikalar içinde wiki'de yayına girer.

## Bilgisayarında çalış (ileri seviye)

Yeni kategoriler, büyük yeniden yazımlar ya da tek seferde çok sayıda dosya için yerelde çalış. Node 22+, Git ve bir kod editörüne ihtiyacın var.

```bash
git clone https://github.com/<your-username>/divine-wiki.git
cd divine-wiki
npm install
npm run dev
```

Önce [github.com/DivineSkins/divine-wiki](https://github.com/DivineSkins/divine-wiki) reposunu fork'la, sonra fork'unu klonla. Sitenin yüklendiğini görmek için `http://localhost:3000` adresini aç. Bir branch oluştur, `content/docs/en/lol/` altındaki dosyaları değiştir, görselleri `public/wiki-images/` içine bırak, sonra push et ve `main`'e bir pull request aç.

## Yardım mı lazım?

- GitHub'da ya da editörde mi takıldın? Discord'da `#wiki-feedback` kanalında sor.
- Yeni bir kategori ya da yeniden yapılandırma gibi büyük bir değişiklik mi planlıyorsun? Önce `#wiki-proposals` kanalına yaz. Bu, reddedilecek bir işi yapmaktan seni kurtarır.
