A Deadlock mod is a small file that swaps some of the game's files for yours. This page explains how the game finds those files and which one wins. Read it before your first mod. It can save you hours when a mod does nothing.

## What you need

- Nothing to install. This page explains ideas, not steps.
- Optional: Source 2 Viewer, to look inside the game files while you read. [Set up your creator tools](/docs/deadlock/getting-started/creator-setup) shows how to install it.

## Everything ships in VPK files

Deadlock runs on Valve's Source 2 engine. Inside the game files it is called `citadel`, so you see that name in many folders.

The game packs its content into VPK archives:

- `game/citadel/pak01_dir.vpk` is the main index. It lists about 150,000 files.
- The data sits in numbered chunk files next to it, from `pak01_000.vpk` up to about `pak01_326.vpk`. Open only the `_dir` file. Tools read the chunks with it.
- `game/core/pak01_dir.vpk` holds shared engine files.
- Each map is its own VPK in `game/citadel/maps/`.

The main folders inside `pak01_dir.vpk`:

| Folder         | What it holds                                                                                                                          |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `models/`      | Models, their materials and textures, animation clips, and skeletons. Heroes are in `models/heroes_wip/` and `models/heroes_staging/`. |
| `materials/`   | Shared materials and textures.                                                                                                         |
| `sounds/`      | Audio files. Most of them are voice lines.                                                                                             |
| `soundevents/` | Scripts that pick which sound plays for each game event.                                                                               |
| `particles/`   | Effects. Hero abilities are in `particles/abilities/`.                                                                                 |
| `panorama/`    | The interface: images, layouts, and styles.                                                                                            |
| `animgraphs/`  | Animation graphs that drive hero animations.                                                                                           |
| `scripts/`     | Game data, such as hero and ability stats. Never put these in a mod.                                                                   |

## Compiled files end in `_c`

Every file inside the VPK is compiled. That means it is saved in a fast binary format the game reads. Compiled file names end in `_c`, like `inferno.vmdl_c`.

You never edit a `_c` file directly. The workflow is always:

1. Decompile the game file with Source 2 Viewer. You get a source file you can edit.
2. Edit the source file in an image editor, audio editor, or text editor.
3. Compile it with CSDK 12. The tools write a new `_c` file.

| You edit               | The game reads                 | What it is                                       |
| ---------------------- | ------------------------------ | ------------------------------------------------ |
| `.vmdl`                | `.vmdl_c`                      | Model                                            |
| `.vmat`                | `.vmat_c`                      | Material: which textures a surface uses, and how |
| `.png`, `.tga`, `.psd` | `.vtex_c`                      | Texture                                          |
| `.wav`, `.mp3`         | `.vsnd_c`                      | Sound                                            |
| `.vsndevts`            | `.vsndevts_c`                  | Sound event script                               |
| `.vpcf`                | `.vpcf_c`                      | Particle effect                                  |
| `.xml`, `.css`, `.js`  | `.vxml_c`, `.vcss_c`, `.vjs_c` | Interface files                                  |

## A mod replaces files by path

The game looks up every file by its path. Billy's model, for example, is `models/heroes_wip/punkgoat/punkgoat.vmdl_c`.

If your mod holds a file at exactly that path, with exactly that name, the game uses your file instead. That is the whole trick. It also explains the most common problem: one wrong letter or folder, and the game quietly uses its own file.

Three things follow from this:

- Folder names use Valve's codenames, not hero names. Billy is `punkgoat`. Look up every hero in [Hero names and file paths](/docs/deadlock/basics/hero-codenames).
- A mod holds compiled `_c` files only. A loose `.png` or `.wav` in a mod does nothing.
- Copy each game path exactly, including every folder.

<Callout type="info" title="Who sees your mod">
  Mods change files on your PC only. You see a skin on every player using that
  hero, enemies included. Other players see the normal game. That is also why a
  skin can give an unfair advantage by accident. [What's allowed and how to stay
  safe](/docs/deadlock/getting-started/stay-safe) explains where the line is.
</Callout>

## How the game finds your mods

The file `game/citadel/gameinfo.gi` tells the game where to look for files. A part of it called `SearchPaths` lists folders in order.

- The game checks the folders from top to bottom. It uses the first copy of a file it finds.
- Valve's own `gameinfo.gi` does not list the `addons` folder. So by default, the game ignores mods.
- A mod manager, or you by hand, adds the line `Game citadel/addons` above `Game citadel`.
- When the game reads a folder, it loads every file named `pak01_dir.vpk` to `pak99_dir.vpk` in it. Other names are ignored.

With the edit in place, the main folders are checked in this order:

1. `citadel/addons`: your mods.
2. `citadel`: the game's own files.
3. `core`: shared engine files.

Because your mods come first, your files win.

Every game update and every Steam "Verify integrity of game files" puts back Valve's `gameinfo.gi`. Your mods stay in the folder, but they stop loading until the line is added again. A mod manager does this for you. The exact edit is in [Install mods by hand](/docs/deadlock/getting-started/install-by-hand).

Only ever change the `SearchPaths` part. Edits to other parts of `gameinfo.gi` can block matchmaking.

## Load order

When you use more than one mod, load order decides what you see.

- Two mods that change different files both work.
- Two mods that ship the same file: the lower number wins. `pak01_dir.vpk` beats `pak05_dir.vpk`.
- Two mods can also break each other if each one changes part of the same shared file. Order does not fix that. Pick one.
- The game loads up to 99 mod files per folder. Mod managers get around this by adding more folders.

So if your mod seems to do nothing, check whether another mod with a lower number changes the same file.

## What a mod must never contain

<Callout type="warning" title="Keep these out of every mod">
  Gameplay data and skeletons break after patches and can break other players'
  mods too.
</Callout>

- **Gameplay data (`scripts/*.vdata_c`).** These files hold hero and ability stats. They go stale with every patch. One popular skin shipped hero data and kept a new hero locked after an update. Changing gameplay data is also not a cosmetic mod.
- **Skeleton files (`.vnmskel_c`).** A shipped skeleton replaces the hero's real one. When Valve changes the rig, animations break for your mod and for other mods of that hero.
- **Programs.** A mod is a `.vpk` file, often inside a `.zip`, `.rar`, or `.7z`. It never needs an `.exe`, `.dll`, `.bat`, `.ps1`, or `.scr` file.
- **Anything that gives an advantage.** See [What's allowed and how to stay safe](/docs/deadlock/getting-started/stay-safe).

[Pack your mod into a VPK](/docs/deadlock/basics/pack-a-vpk) has the full list of what goes in and what stays out.

## Why patches break mods

Valve updates Deadlock often. Big updates break many mods at once. The "City Never Sleeps" update on 2026-09-29 broke most HUD mods, for example. Common reasons:

- **Models move.** Abrams moved from `heroes_staging/atlas_detective_v2/` to `heroes_wip/abrams/`. A mod at the old path stops working without any error.
- **Animations change.** Valve keeps moving heroes to a newer animation system. Replacement models must point to the new files.
- **Skeletons and cameras change.** Old skins can end up with a camera stuck in the middle of the screen.
- **Interface layouts change.** Outdated HUD mods can crash the game at launch.
- **`gameinfo.gi` gets replaced.** Mods stop loading until the addons line is back.

After a big update, check your paths again in [Hero names and file paths](/docs/deadlock/basics/hero-codenames). Then recompile and repack. A full guide to updating your mod is coming. {/* LINK LATER: /docs/deadlock/publishing/update-after-a-patch */}
