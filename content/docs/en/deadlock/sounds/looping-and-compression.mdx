## Which sounds loop

Some sounds play once, like a gunshot. Others repeat for as long as an ability is active, like an ultimate or a channel. Many looping sounds have `lp` in their name, such as `forge_rocket_barrage_air_raid_lp`.

Two separate settings control a looping sound:

<img
  src="/wiki-images/deadlock-sounds-looping-and-compression-1.webp"
  alt="Two settings: loop points in encoding.txt decide which part of the sound repeats, and the duration in the soundevent decides how long the game plays it"
/>

| Setting         | What it decides                   | Where you set it                                 |
| --------------- | --------------------------------- | ------------------------------------------------ |
| **Loop points** | Which part of your audio repeats  | `encoding.txt`                                   |
| **Duration**    | How long the game plays the sound | The hero's soundevents file, for some loops only |

<Callout type="danger" title="Keep loops fair">
  Keep a looping sound as loud as the original. Never make an enemy ability
  sound louder, clearer, or longer than the ability itself. Read [What's allowed
  and how to stay safe](/docs/deadlock/getting-started/stay-safe).
</Callout>

## Set loop points

<Steps>
<Step>

### Use WAV for loops

Loop points only work with `.wav` source files. MP3 is fine for sounds that play once.

1. Export your audio as `.wav` from your audio editor.
2. Give it the exact name of the original sound. Only the ending changes, for example `example_sound_lp.wav`.
3. Save it at the original path in your addon's content folder.
4. Delete any `.mp3` copy with the same name from that folder, so only the `.wav` is left.

</Step>
<Step>

### Check for lame_enc.dll

Looping also needs a file called `lame_enc.dll` in CSDK 12's `bin` files.

1. Open your CSDK 12 folder.
2. Search it for `lame_enc.dll`.
3. If the search finds nothing, ask in the Deadlock Modding Discord. Never download a `.dll` from a random website.

</Step>

### Find the loop points

1. Open your `.wav` in your audio editor.
2. Select the part that should repeat.
3. Write down the start and end of the selection, in seconds.
4. Play the jump from the end back to the start. If you hear a click, move the points a little and try again.

You can use sample numbers instead of seconds. They are more exact, but they depend on your file's sample rate.

### Write encoding.txt

1. Open the folder in your addon's content folder that holds your `.wav`. For example: `content/citadel_addons/mysound/sounds/abilities/<codename>/`.
2. Turn on file name extensions in File Explorer.
3. Create a new text file in that folder named `encoding.txt`. Check that it does not end in `.txt.txt`.
4. Copy the `encoding.txt` template from the [Replacing Sounds](https://deadlockmodding.pages.dev/modding-guides/replacing-sounds) guide into your file. Its first line starts with `<!-- kv3`. Keep that line exactly as it is.
5. Under `files`, keep one block per looping sound. Delete the other example blocks.
6. Set `fileName` to your `.wav` file name.
7. Set `loop_start_time` and `loop_end_time` to your loop points, in seconds.
8. Save the file.

Below the first line, your file should look like this:

```text
{
	compress =
	{
		format = "mp3"
		minbitrate = 128
		maxbitrate = 320
		vbr = 1
	}
	files =
	[
		{
			fileName = "example_sound_lp.wav"
			loop =
			{
				loop_start_time = 0.5
				loop_end_time = 6.25
			}
		},
	]
}
```

To use sample numbers, swap the two loop lines for these:

```text
				loop_start_sample = 22050
				loop_end_sample = 275625
```

<Step>

### Compile and test

1. Launch the CSDK 12 tools for your addon.
2. In the Asset Browser, right-click your sound and choose <MenuPath path="Recompile > Full" />.
3. Pack the compiled `.vsnd_c` and test it. Follow [Pack your mod into a VPK](/docs/deadlock/basics/pack-a-vpk) and [Test your mod in game](/docs/deadlock/basics/test-your-mod).

While the CSDK 12 tools are open, saving `encoding.txt` also recompiles the sounds it lists. This makes it quick to try new loop points.

</Step>
</Steps>

## Compress big sound mods

WAV files are large, so a pack of them makes a huge VPK. The `compress` block makes CSDK 12 compile the sounds as MP3 instead.

```text
	compress =
	{
		format = "mp3"
		minbitrate = 128
		maxbitrate = 320
		vbr = 1
	}
```

| Key                        | What it does                                                       |
| -------------------------- | ------------------------------------------------------------------ |
| `format`                   | Sets the compressed format.                                        |
| `minbitrate`, `maxbitrate` | Set the quality range. Higher means better sound and bigger files. |
| `vbr = 1`                  | Lets the bitrate change with the sound.                            |

In the community guide, one sound shrank from 19.7 MB to 1.97 MB and kept its loop points.

To compress every sound in your addon, put one `encoding.txt` in the addon's `sounds` folder, with only the `compress` block inside the outer braces. The community guide says this should work, but we have not tested it. If a folder also has its own `encoding.txt` with loop points, add the `compress` block to that file too.

## Make a loop play long enough

Some looping ability sounds have a set duration in the hero's soundevents file. Mo & Krill's burrow loop is one example. If your audio is longer than that duration, the game restarts it before it ends.

1. Copy the hero's soundevents file into your addon and edit it. [Play random sounds with soundevents](/docs/deadlock/sounds/random-sounds) shows how.
2. Find the event for your looping sound.
3. Raise its duration so your audio fits. Raise it only as far as your audio needs.
4. Compile the soundevents file and your sound, then pack both.

## Common problems

<Accordions>
<Accordion title="The loop points do nothing">

Your source is an `.mp3`, `lame_enc.dll` is missing, or `fileName` does not match your `.wav` name exactly.

</Accordion>
<Accordion title="The compile fails after you add encoding.txt">

Check that the first `<!-- kv3` line is intact and that every `{`, `}`, `[`, and `]` has a partner.

</Accordion>
<Accordion title="The loop restarts too early">

The soundevent's duration is shorter than your audio. See [Make a loop play long enough](#make-a-loop-play-long-enough).

</Accordion>
<Accordion title="You hear a click where the loop starts again">

Move the loop points a little, then save `encoding.txt` again.

</Accordion>
<Accordion title="A loop keeps playing in the tools after you close the preview">

One creator saw this and ignored it. It happens only in the tools.

</Accordion>
<Accordion title="The VPK is huge">

Add the `compress` block.

</Accordion>
</Accordions>
