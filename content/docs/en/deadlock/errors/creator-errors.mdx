Fixes for errors you hit while making a mod: CSDK 12 problems, failed compiles, packing mistakes, and changes that never show in game. Model and skin errors have their own page: [Model and skin problems](/docs/deadlock/errors/model-problems).

## What you need

<ToolCard name="CSDK 12" href="/docs/deadlock/tools/csdk-12">
  The community Source 2 tools. Its page covers the binaries and launcher
  options.
</ToolCard>
<ToolCard name="Source 2 Viewer" href="/docs/deadlock/tools/source-2-viewer">
  Opens game files and VPKs, so you can compare paths and sizes.
</ToolCard>

- Your addon's content folder and game folder. Right-click the addon in the CSDK 12 launcher to open them.

## CSDK 12 will not start, or your addon is missing

<Accordions type="multiple">
<Accordion title="The tools do not open" id="the-tools-do-not-open">

Start Steam first. CSDK 12 needs it running.

</Accordion>
<Accordion title="The tools fail to start or crash from your Desktop or Documents folder" id="the-tools-crash-from-desktop-or-documents">

OneDrive often syncs those folders, and that breaks CSDK 12. Move the `Reduced_CSDK_12` folder to a short path, such as `C:\Reduced_CSDK_12`.

</Accordion>
<Accordion title="Your addon is missing from the launcher" id="your-addon-is-missing-from-the-launcher">

Its name has a capital letter, a space, or a special character.

1. Rename the folder in both `content/citadel_addons/` and `game/citadel_addons/`, all lowercase with no spaces.
2. Click **Refresh addons list**.

{/* SCREENSHOT: deadlock-errors-creator-errors-1.webp, the CSDK 12 launcher addon list, with File Explorer next to it showing a content folder named MyMod that does not appear in the list */}

</Accordion>
<Accordion title="You cannot find the launcher" id="you-cannot-find-the-launcher">

It is `csdkcfg.exe` in your `Reduced_CSDK_12` folder. Older CSDK 12 downloads used a different file. The CSDK 12 page names the current one.

{/* NEEDS HANDS-ON TEST: the launcher exe name in the current CSDK 12 zip (conflict C22). Older guides open game\bin\win64\Deadlock_with_tools.exe, the "Project8 CFG Tool". */}

</Accordion>
<Accordion title="bin_server will not start" id="bin-server-will-not-start">

It needs the optional full game files. Switch the binary picker back to `bin`.

</Accordion>
</Accordions>

## The tools crash

<Accordions type="multiple">
<Accordion title="A crash when you preview some particle effects" id="a-crash-when-you-preview-particle-effects">

The `bin` binary crashes on some projected particles. Switch the binary picker to `bin_tools` for that preview. Switch back afterwards, because `bin_tools` crashes on some model compiles.

</Accordion>
<Accordion title="ModelDoc crashes, or a decompiled model will not open" id="modeldoc-crashes">

</Accordion>

## Compile errors

Compile errors show in VConsole, the console window that opens when you launch the tools. Read it after each compile.

{/* SCREENSHOT: deadlock-errors-creator-errors-2.webp, VConsole showing a compile error for a file in our own test addon */}

<Accordions type="multiple">
<Accordion title="Nothing compiles" id="nothing-compiles">

1. Check that the file sits inside your addon's content folder, at the same path it has in the game.
2. Right-click it in the Asset Browser and choose **Recompile > Full**.

</Accordion>
<Accordion title="A .vpdi file will not compile" id="a-vpdi-file-will-not-compile">

The CS2 Workshop Tools cannot compile `.vpdi` files. Use an `image_compiler.vdata` file instead. [Replace portraits, icons, and item art](/docs/deadlock/ui/portraits-and-icons) shows how.

</Accordion>
<Accordion title="image_compiler.vdata fails" id="image-compiler-vdata-fails">

Check that every line names a real image file, ending included. One older guide compiles it with the `bin_server` binary, which needs the full game files.

{/* NEEDS HANDS-ON TEST: which CSDK 12 binary compiles image_compiler.vdata without the full game files (conflict C44). Test the default bin first. */}

</Accordion>
<Accordion title="A texture at an odd size causes trouble" id="a-texture-at-an-odd-size">

The compiler makes smaller copies of each texture, called mipmaps. They expect sizes like 512, 1024, or 2048. Use those sizes.

</Accordion>
</Accordions>

## Your change does not show in game

This is the most common creator problem. Your edit has to survive five steps, and each one has a usual mistake.

<img
  src="/wiki-images/deadlock-errors-creator-errors-3.webp"
  alt="Five steps from source file to game: content folder, Recompile > Full, copy from the game folder, pack one VPK, load from citadel/addons. Each step shows its usual mistake."
/>

Check these in order:

<Steps>
<Step>

### Recompile

Right-click the file in the Asset Browser and choose **Recompile > Full**. Saving the source file is not enough.

</Step>
<Step>

### Copy from the game folder

Your mod needs the compiled `_c` file from `game/citadel_addons/<addon>/`. The content folder holds source files, which the game ignores. A `.vmat` in a mod does nothing. A `.vmat_c` works.

</Step>
<Step>

### Match the path

The path inside your VPK must match the game's path letter for letter. Compare it with `pak01_dir.vpk` in Source 2 Viewer.

</Step>
<Step>

### Keep the original name

The game only loads a file with the original name. If you worked under another name, rename the compiled file back.

</Step>
<Step>

### Ship the textures too

A recompiled material points to new texture files with a hash in the name, such as `abrams_coat_color_png_63291cfb.vtex_c`. Pack the new `.vtex_c` files next to the `.vmat_c`.

</Step>
<Step>

### Check the VPK

Name it `pakNN_dir.vpk` and put it straight into `game/citadel/addons/`. A mod with a lower number that changes the same file wins. [Mods not loading](/docs/deadlock/errors/mods-not-loading) covers the rest of the player-side checks.

</Step>
</Steps>

## Packing problems

<Accordions type="multiple">
<Accordion title="Source 2 Viewer fails to build the VPK" id="source-2-viewer-fails-to-build-the-vpk">

Update to the latest dev build from [s2v.app](https://s2v.app/). Older releases had VPK building errors.

</Accordion>
<Accordion title="Paths in the VPK start at the wrong folder" id="paths-start-at-the-wrong-folder">

Every path must start at a game folder, such as `models/` or `sounds/`. It must not start at your staging folder's name, or halfway down at `heroes_wip/`. Fix your staging folder and pack again.

</Accordion>
<Accordion title="Source 2 Viewer shows the same file twice in your new VPK" id="the-same-file-shows-twice">

One creator reports these are phantom copies, and deleting one deleted the real file. Leave them alone.

{/* NEEDS HANDS-ON TEST: Source 2 Viewer's phantom duplicate entries in a new VPK (one source, Adamtheboss9's sound video). */}

</Accordion>
<Accordion title="The CS2 Workshop Manager says Submit failed" id="submit-failed">

That is expected. It still writes the VPK.

</Accordion>
<Accordion title="A VPK over 2 GB fails" id="a-vpk-over-2-gb-fails">

One VPK from the CS2 Workshop Manager is limited to 2 GB. See [Mods bigger than 2 GB](/docs/deadlock/basics/pack-a-vpk#mods-bigger-than-2-gb).

</Accordion>
</Accordions>

## Material and texture problems

<Accordions type="multiple">
<Accordion title="Purple checkerboard in the Material Editor" id="purple-checkerboard-in-the-material-editor">

A texture slot lost its image, often after you moved files.

1. Click the magnifier on each texture slot.
2. Pick the image that came with the material.
3. Save.

{/* SCREENSHOT: deadlock-errors-creator-errors-4.webp, the purple checkerboard in the Material Editor on a material from our own test addon, with the magnifier button on a texture slot visible */}

</Accordion>
<Accordion title="Checkerboard or missing texture in game" id="checkerboard-or-missing-texture-in-game">

The new `.vtex_c` files are missing from your VPK. Pack them with the `.vmat_c`.

</Accordion>
<Accordion title="Black squares or odd shading in Source 2 Viewer" id="black-squares-in-source-2-viewer">

The viewer's Deadlock shading is still a work in progress. Check the material in game before you change anything.

</Accordion>
<Accordion title="A red model in ModelDoc or the CS2 tools" id="a-red-model">

See [The mesh is solid red](/docs/deadlock/errors/model-problems#the-mesh-is-solid-red-or-shows-checkerboards) on the Model and skin problems page.

</Accordion>
</Accordions>

## Sound problems

<Accordions type="multiple">
<Accordion title="The game plays the old sound" id="the-game-plays-the-old-sound">

Your path or file name differs from the original. Compare every letter with Source 2 Viewer.

</Accordion>
<Accordion title="Nothing changes" id="nothing-changes">

You copied the source audio from the content folder. Copy the `.vsnd_c` from the game folder.

</Accordion>
<Accordion title="Another sound mod wins" id="another-sound-mod-wins">

The lower pak number wins. Two mods that each replace a hero's whole soundevents file also clash, and only one can win.

</Accordion>
<Accordion title="The sound is too quiet or plays too high" id="the-sound-is-too-quiet-or-too-high">

One creator traced this to outdated tools and to hero soundevents that raise the pitch.

1. Use the current Reduced CSDK 12.
2. Open the hero's file in `soundevents/hero/`.
3. Look for a pitch value on that sound before you change your audio.

</Accordion>
<Accordion title="Loop points are ignored" id="loop-points-are-ignored">

Loops need `.wav` source files and `lame_enc.dll` in the CSDK 12 `bin` folder. This comes from one guide written before the latest update. See [Loop and compress sounds](/docs/deadlock/sounds/looping-and-compression).

</Accordion>
</Accordions>

## UI image problems

<Accordions type="multiple">
<Accordion title="The image is stretched, cropped, or blurry" id="the-image-is-stretched-cropped-or-blurry">

Its size does not match the original. Check the width and height in Source 2 Viewer and remake it. Keep a transparent background.

</Accordion>
<Accordion title="The game shows the old image" id="the-game-shows-the-old-image">

The compiled name differs from the original. Older guides rename `_png.vtex_c` files to the original `_psd.vtex_c` name.

{/* NEEDS HANDS-ON TEST: the _png to _psd rename rule on build 6779 (conflict C42). */}

</Accordion>
<Accordion title="Another hero's icons changed too" id="another-heros-icons-changed-too">

You left the template's sample images in your addon. Delete them and pack again.

</Accordion>
</Accordions>

## Particle problems

<Accordions type="multiple">
<Accordion title="The color does not change, or changes only partly" id="the-color-does-not-change">

The effect has more than one color source. Change every property with "color" in its name, plus the renderer settings. Check the effect's Children list too, because child effects have their own colors.

</Accordion>
<Accordion title="You recolored the wrong file" id="you-recolored-the-wrong-file">

Many effects in a hero's folder are not used. Type `dumpparticlelist` in the console during a private match to list the effects in use. [Test your mod in game](/docs/deadlock/basics/test-your-mod) shows how to open the console.

</Accordion>
<Accordion title="A newer particle does not open in the Particle Editor" id="a-newer-particle-does-not-open">

One video fix: open the `.vpcf` in a text editor and change its first line. We have not tested it on the current build.

The first line changes from this:

```text
<!-- kv3 encoding:text:version{e21c7f3c-8a33-41c5-9977-a76d3a32aa0d} format:vrfunknown:version{c95f3434-dfef-4a35-9913-024beddb416a} -->
```

To this:

```text
<!-- kv3 encoding:text:version{e21c7f3c-8a33-41c5-9977-a76d3a32aa0d} format:vpcf61:version{39d3ce1d-9442-4407-9b78-8317145b1732} -->
```

</Accordion>
</Accordions>
