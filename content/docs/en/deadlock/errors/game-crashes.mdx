Deadlock crashes, shows a `FATAL ERROR`, or will not let you queue. Start with the first check: it tells you whether a mod or the game is at fault. Then find your error below. Each fix is titled with the exact error text, so you can search this page with **Ctrl+F**.

Mods do nothing, but the game runs fine? Go to [Mods not loading](/docs/deadlock/errors/mods-not-loading).

## First: is it a mod or the game?

<img
  src="/wiki-images/deadlock-errors-game-crashes-1.webp"
  alt="Flow chart: back up the addons folder, move every VPK out, start Deadlock. If it still crashes, verify game files. If it starts, add mods back one at a time until the crash returns."
/>

<Steps>
<Step>

### Empty the addons folder

1. Close Deadlock and your mod manager.
2. Copy `game/citadel/addons` to your desktop as a backup.
3. Open `addons` and move every `.vpk` file out of it.

Touch only files inside `addons`. The `.vpk` files directly in `citadel` belong to the game.

</Step>
<Step>

### Start the game

1. Start Deadlock.
2. Still crashes? The game is at fault, not a mod. In Steam, right-click **Deadlock** and choose <MenuPath path="Properties > Installed Files > Verify integrity of game files" />. Wait for it to finish.
3. Starts fine? A mod is at fault. Go to the next step.

</Step>
<Step>

### Put your mods back one at a time

1. Put back one mod, then start the game.
2. Repeat until the crash comes back. The last mod you added caused it.
3. Leave that mod out and check its GameBanana page for an update.

With many mods, put back half at a time instead. Keep halving the group that crashes until one mod is left.

</Step>
</Steps>

With Deadlock Mod Manager, click **Disable all mods** instead of moving files. Then switch mods back on one at a time.

<Callout type="info" title="Verify resets gameinfo.gi">
  Before you put mods back, redo the [addons
  line](/docs/deadlock/getting-started/install-by-hand#edit-gameinfogi), or
  click **Launch Modded** in your manager.
</Callout>

Reinstalling Deadlock does not help. Steam leaves the `addons` folder on disk, so old mods keep crashing the game. Empty `addons` by hand.

## Errors at launch

<Accordions type="multiple">
<Accordion title='"Unable to find child" in a layout file' id="unable-to-find-child-at-launch">

**You see:** the game closes at the Valve logo with an error like this:

```text
FATAL ERROR: Unable to find child 'ParryCooldownBorder' in layout file 'panorama\layout\ability_hud_elements\element_gun.xml'
```

The names in quotes change. `Unable to find child` and `layout file` stay the same.

{/* SCREENSHOT: deadlock-errors-game-crashes-2.webp, the FATAL ERROR dialog from an outdated HUD file. Reproduce it with an old HUD VPK of our own making, not a third-party HUD pack. */}

**Cause:** an outdated HUD mod. Big updates change the game's interface files, and a HUD mod made for the old files no longer fits. Outdated HUD mods such as QOL Lock and Top Bar Plus are the most common cause. Other interface errors at launch, such as top bar errors, have the same cause.

**Fix:**

1. Remove your HUD mods from `addons`, or switch them off in your manager.
2. Start the game to check that it works.
3. Check each HUD mod's page for an update. Install the new version when it is out.

After a big update, such as City Never Sleeps on 2026-09-29, most HUD mods break at once. Mod authors need time to catch up.

</Accordion>
<Accordion title='"Error parsing KV3 data"' id="error-parsing-kv3-data">

**You see:**

```text
FATAL ERROR: Error parsing KV3 data in 'scripts/abilities.vdata' for entity subclass ...
```

**Cause:** a mod ships an old copy of a gameplay data file. The file named in the error, here `scripts/abilities.vdata`, no longer matches the game.

**Fix:**

1. Note the file path in the error.
2. Open each of your mods in Source 2 Viewer with <MenuPath path="File > Open" />.
3. Find the mod that holds that file. Inside the VPK its name ends in `_c`, such as `scripts/abilities.vdata_c`.
4. Remove that mod.

With many mods, the half-and-half test in [the first check](#first-is-it-a-mod-or-the-game) is faster.

{/* SCREENSHOT: deadlock-errors-game-crashes-3.webp, Source 2 Viewer showing a mod VPK of our own that contains scripts/abilities.vdata_c */}

Old gameplay data can also cause quieter problems. A new hero can stay locked, or hero stats can stay at old values. Cosmetic mods should never contain `scripts/` files. Creators, see [What a mod must never contain](/docs/deadlock/basics/how-mods-work#what-a-mod-must-never-contain).

</Accordion>
<Accordion title='"Failed to parse KeyValues"' id="failed-to-parse-keyvalues">

**You see:** the game will not start, with one of these messages:

```text
Application unable to load gameinfo.gi file from directory "citadel"
Failed to parse KeyValues
```

**Cause:** a typo in your `gameinfo.gi` edit. Usually a `{` or `}` is missing.

**Fix:**

1. Run **Verify integrity of game files** in Steam. This puts back Valve's clean file.
2. Redo the edit with the full block from [Install mods by hand](/docs/deadlock/getting-started/install-by-hand#edit-gameinfogi). Replace only the lines of the `SearchPaths` block.
3. Check that every `{` has a matching `}`.

</Accordion>
<Accordion title='"Unable to read default keybinding configuration"' id="unable-to-read-default-keybinding-configuration">

**You see:** the game crashes at launch with this message:

```text
Unable to read default keybinding configuration
```

**Cause:** your `SearchPaths` block has the addons line but is missing the `Mod` and `Write` lines.

**Fix:**

1. Paste the full block from [Install mods by hand](/docs/deadlock/getting-started/install-by-hand#edit-gameinfogi).
2. If a mod manager wrote the block, update the manager to its latest version. Then launch through it again.

</Accordion>
</Accordions>

## Matchmaking, replays, and menus

<Accordions type="multiple">
<Accordion title='Matchmaking is blocked: "Unable to enter matchmaking"' id="matchmaking-is-blocked">

**You see:** you try to queue and get this message:

```text
Unable to enter matchmaking while any party member is running Tools-mode, or has unsupported changes to the following sections of their 'gameinfo.gi': Engine2, MaterialSystem2, NetworkSystem, Particles, RenderSystem, SceneSystem, WorldRenderer
```

{/* SCREENSHOT: deadlock-errors-game-crashes-4.webp, the matchmaking-blocked dialog, triggered by queueing with CSDK 12 open on a test account (same shot as deadlock-getting-started-stay-safe-1.webp) */}

**Cause:** someone in your party has creator tools open, or changed one of those parts of `gameinfo.gi`. "Performance" config files from the internet change these parts. The `SearchPaths` edit for mods is not on this list.

**Fix:** every party member checks:

1. Close CSDK 12 and every other creator tool.
2. Run **Verify integrity of game files** in Steam.
3. Redo only the addons line. Follow [Install mods by hand](/docs/deadlock/getting-started/install-by-hand#edit-gameinfogi), or click **Launch Modded** in your mod manager.
4. Queue again.

Custom maps also do not work in Valve matches. Before you queue, move the custom map files you added out of `game/citadel/maps/`. Leave Valve's own maps there. In Deadlock Mod Manager, use **Disable Map Mods & Launch**.

</Accordion>
<Accordion title="Replays fail to save or play" id="replays-fail-to-save-or-play">

**You see:** a replay error such as one of these:

```text
citadel_replay_manager_error_partial_decompression_failure
citadel_replay_manager_error_existing_partial
```

**Cause:** with mods on, the game saves replays in `citadel/addons/replays` instead of its normal replay folder.

**Fix:** Deadlock Mod Manager links the two replay folders for you, so this mostly affects hand-edited installs. We have not tested a fix for hand-edited installs on the current build yet.

Test that fix, and test that DMM's replay symlink works, before adding steps here. */}

</Accordion>
<Accordion title="Menu text shows #menu_news" id="menu-text-shows-menu_news">

**You see:** menu labels show code names that start with `#`, such as `#menu_seasonal_2025` or `#menu_news`.

**Cause:** the game's text files are damaged or out of date, or an old mod replaces them.

**Fix:**

1. Remove mods that change text or menus.
2. Run **Verify integrity of game files** in Steam.

This fix comes from a guide written in December 2025. It may differ on the current build.

</Accordion>

## It crashes with no mods at all

If the game crashes even with an empty `addons` folder, a game file may be damaged.

1. Run **Verify integrity of game files** in Steam.
2. Check that `addons` is really empty, including subfolders.
3. Check for extra mod folders a manager made in `game/citadel/`, such as `addons2`. Empty those too.

If it still crashes, mods are not the cause. [Find mods, guides, and help](/docs/deadlock/getting-started/where-to-get-help) lists places to ask.
