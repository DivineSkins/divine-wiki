<LevelPill level="intermediate" />

Fix tools repair most old Wuthering Waves mods. When the tool has no release for your game version yet, or one texture still looks wrong after it, you can fix some problems in the `mod.ini` yourself. Many breaks in this game need a setting, a launcher update or a new export instead, so this page also shows what no edit can fix. Written for WWMI 1.2.2 and WWMI Tools 1.9.4 on version 3.8.

<Accordions>
<Accordion title="Coming from another game?">

Each game broke its mods in its own way, so the fixes differ.

- **Genshin Impact:** the big break is 6.1. Texture slots moved, so every character part needs an ORFix or NNFix line.
- **Honkai: Star Rail:** version 3.2 moved skinning to compute shaders, and textures bind by hash.
- **Zenless Zone Zero:** textures bind through SlotFix (`Resource\ZZMI\...`).
- **Wuthering Waves:** most breaks are changed texture hashes and lower-detail models. There is no fix line to add. Very old mods need a new export from WWMI Tools. Mods exported with WWMI Tools 1.9.4 find their textures by look instead of by hash.

Other game sections: [Genshin Impact](/docs/genshin-impact), [Honkai: Star Rail](/docs/honkai-star-rail), [Zenless Zone Zero](/docs/zenless-zone-zero).

</Accordion>
</Accordions>

## Try the fixes without edits first

Many "broken" mods work again with no edit at all: update XXMI Launcher, then check **Client Resource Quality**, **Mesh LOD Base FOV** and the in-game **LOD Bias**. [Fix your mods after a game update](/docs/wuthering-waves/getting-started/fix-mods-after-an-update) has the order, and [Update fix tools](/docs/wuthering-waves/tools/update-fixers) covers Wuwa_Mod_Fixer and WuWa_MOD_WojuFixer.

Fix by hand when:

- no fix tool has a release for your game version yet;
- the tool fixed most of the mod, but one texture still looks wrong;
- you want to know what the tool changed.

WWMI Tools 1.9.4 exports: replace the dHash |
| Textures wrong only in the open world or from far away                                                                   | The game loads lower-detail textures                             | Settings, not an edit: **LOD Bias** at **Ultra High**                                                        |

[Make mods show at a distance](/docs/wuthering-waves/models/lods)                     |

No hand fix                                                             |
| Faces or shading wrong on several unrelated Resonators                                                                   | One outdated mod still ships an old shared texture               | Find that mod by halves. See [Mods look broken](/docs/wuthering-waves/errors/mods-look-broken)               |
| Limbs or accessories stretch                                                                                             | An old export, from before WWMI Tools 1.3.0                      | A new export with WWMI Tools 1.9.4                                                                           |

A Resonator is a playable character. Rover breaks most often: version 3.8 broke Rover mods and facial expressions again.

A few breaks have no hand fix in any guide:

- **Parts missing on mods made before 3.3.** Wuwa_Mod_Fixer has an optional fix for the 3.3 rendering change.
- **Half of the model see-through from behind,** since 3.0. One community guide adds a custom shader for it. It can clash with see-through effects, so it is not covered here.

## Fix it by hand

<Steps>
<Step>

### Back up and turn on warnings

1. Copy the mod's folder to a place outside `Mods`.
2. In XXMI Launcher, open the settings, go to the **WWMI** tab and untick **Mute Warnings**. Now `F10` shows errors in game.
3. Open the mod's `mod.ini` in your text editor.

</Step>
<Step>

### Check the format and the WWMI version

Look at two lines:

- **The first line** names the format, like `; WWMI BETA-11 INI` for WWMI Tools 1.9.4 or `; WWMI BETA-9 INI` for 1.8.0. A `BETA-11` mod binds its textures by look: fix a texture with [Fix a WWMI Tools 1.9.4 export](#fix-a-wwmi-tools-194-export). An older mod binds them by hash: follow the steps on this page. A merged-skeleton mod with a format older than `BETA-5` was exported before WWMI Tools 1.5.1 (January 26, 2026). It may misbehave since version 3.0, and only a new export fixes it.
- **`global $required_wwmi_version`** in `[Constants]` is the oldest WWMI the mod works with. WWMI Tools 1.9.4 writes `1.22`, so its mods need WWMI 1.2.2.

If WWMI says the installed version is below the minimum, update WWMI: open XXMI Launcher, click the 3-dots button next to **Start**, then **Check For Updates**. Never lower the number in the file. It is there so WWMI can refuse the mod instead of crashing the game.

</Step>
<Step>

### Find the lines for the broken texture

These steps are for a mod exported with WWMI Tools 1.8.0 or older.

1. Open the mod's `Textures` folder in a DDS viewer, or in your image editor.
2. Find the texture that looks wrong in game. The diffuse holds the real colors. The normal map has the same layout in yellow and grey. The light map looks like a brighter copy of the diffuse.
3. Copy its full file name, like `Components-3 t=cccccccc.dds`.
4. Search the `mod.ini` for it. You land on a `filename =` line in a section like `[ResourceTexture12]`.
5. Find the section with the same number: `[TextureOverrideTexture12]`. Its `hash =` line is the one to update.

The video is from version 3.5 and uses the search to add RabbitFX lines. The search works the same way here. Its component numbers belong to that one mod.

</Step>
<Step>

### Get the new hash

1. Make a frame dump of the Resonator with no mods on it, as [Make a frame dump](/docs/wuthering-waves/basics/frame-dump) shows. Play with the same **Client Resource Quality** as always: each quality tier may have its own texture hashes.
2. Extract it with **Extract Objects From Dump** in WWMI Tools.
3. In the new object folder, find the same texture: the same component number in the name, and the same type. WWMI Tools 1.9.4 names the file like `c=3 f=BC7_UNORM_SRGB t=dddddddd d=0123456789abcdef.dds`, so the component number comes after `c=`. `TextureUsage.json` lists which texture each component uses.
4. The part after `t=` in its file name is the new hash.

No guide documents this way of matching an old texture to a new one, and nobody has tested it yet. A component often has several textures, and the component numbers in a file name can change. So compare the slot in `TextureUsage.json` and the format too, and always check the result in game.

{/* NEEDS HANDS-ON TEST: matching an old texture to its new hash by component number and TextureUsage.json, on a Wuthering Waves 3.8 dump extracted with WWMI Tools 1.9.4, and the exact c=, f=, t= and d= file names it writes */}

</Step>
<Step>

### Replace the hash

In `[TextureOverrideTexture12]`, put the new hash after `hash =`. Keep one hash per line, with nothing after it:

```ini
[TextureOverrideTexture12]
hash = dddddddd
match_priority = 0
if $object_detected
    this = ResourceTexture12
endif
```

You do not need to rename the `.dds` file: `filename` and `hash` are separate lines. Repeat for every texture that is still wrong.

The next update may change the hash again. Mods that bind textures with RabbitFX survive most updates, because they bind each texture by its role. A new export with WWMI Tools 1.9.4 stops depending on the hash too. [Make textures survive game updates](/docs/wuthering-waves/textures/stable-textures) shows how to move a mod to it.

</Step>
<Step>

### Test

1. Save the file as UTF-8.
2. In game, switch to another Resonator, then press `F10`.
3. Switch back. Read any warning text, fix the line it names, and reload.
4. Check every part up close and from far away, while the Resonator moves. Hold `F9` to compare with the original.

</Step>
</Steps>

## Fix a WWMI Tools 1.9.4 export

A mod exported with WWMI Tools 1.9.4 has no texture hash to replace. Each texture has a filter that describes how the game's texture looks. If an update redraws that texture, the filter may stop matching. Update the filter instead:

1. Copy the texture's full file name from `Textures`, like `c=3 f=BC7_UNORM_SRGB t=cccccccc d=0123456789abcdef.dds`.
2. Search the `mod.ini` for it. You land in `[ResourceTexture12]`. The `[FilterTexture12]` section with the same number holds `match_format` and `match_dhash`.
3. Make a fresh frame dump and extract it with WWMI Tools 1.9.4. Find the same texture, as in "Get the new hash" above.
4. Put the part after `d=` in its new file name after `match_dhash =`. If the part after `f=` changed, put it after `match_format =`.
5. Save, press `F10` in game, and check the part up close and far away.

```ini
[FilterTexture12]
match_format = BC7_UNORM_SRGB
match_dhash = 0123456789abcdef
```

The values here are examples. If the right texture still does not match, an optional `match_confidence` line with a value below the default `0.75` lets a less similar texture match. A lower value can also pick the wrong texture, so lower it in small steps. The [.ini reference](/docs/wuthering-waves/ini/ini-reference#filter-keys) lists the filter keys.

## When a new export beats hand edits

If you made the mod, or you have its `.blend` file, export it again with WWMI Tools 1.9.4. Every section then comes out in the current format, and textures bind by look. WWMI Tools 1.9.4 refuses to export from an object folder extracted with an older version, so start from a new frame dump.

When the Resonator's model itself changed, a new export is the only fix:

1. Make a new frame dump of the unmodded Resonator and extract it.
2. Import it with the same skeleton type as before.
3. Make the vertex groups of your custom mesh match the new import.
4. Export into a **new** mod folder.
5. Move your edited textures from the old mod folder into the new one, one by one. The new files have new names: open each new file, find your edited version of the same picture, and save your edit over the new file under its full new name.

Creators updating their own mod for others can follow [Update your mod after a game update](/docs/wuthering-waves/publishing/update-your-mod).

## Common problems

<Accordions type="multiple">
<Accordion title="Still wrong after I replaced the hash" id="still-wrong">

- Check that your dump used the same **Client Resource Quality** you play with.
- Check **LOD Bias** in the game's graphics settings. Below **Ultra High**, the game loads lower-detail textures with other hashes.
- Check that you took the hash of the same texture type: a diffuse for a diffuse, a normal map for a normal map.

</Accordion>
<Accordion title="Another Resonator changed too" id="other-resonator-changed">

Some textures, such as face shadow and light maps, are shared by several Resonators. A mod exported with WWMI Tools 1.8.0 or older replaces them wherever they show while its Resonator is on screen. Remove that texture's two sections if you did not mean to change it. A mod exported with WWMI Tools 1.9.4 changes textures only on its own parts.

</Accordion>
<Accordion title="A fix tool ran twice and the mod is worse" id="tool-ran-twice">

Restore the mod from your backup, then run one tool once. Never run both tools on the same mod.

</Accordion>
<Accordion title="Only this Resonator looks scrambled" id="one-resonator-scrambled">

Another mod for the same Resonator is loaded. Keep one mod per Resonator.

</Accordion>
</Accordions>
