<LevelPill level="beginner" />

Dump folders, the asset repository and Blender objects all use the same names for Resonators and their parts. A Resonator is the game's name for a playable character. Learn the names once here, so you pick the right folder and the right object every time.

<Accordions>
<Accordion title="Coming from another game?">

**From Genshin Impact, Honkai: Star Rail or Zenless Zone Zero.** Wuthering Waves has no `hash.json`, no named parts like `Head`, `Body` or `HairA`, and no part letters. Every object is split into numbered components: `Component 0`, `Component 1` and so on. The numbers do not tell you the body part. A `Metadata.json` file holds the hashes instead, and you may rename the folder.

Other game sections: [Genshin Impact](/docs/genshin-impact), [Honkai: Star Rail](/docs/honkai-star-rail), [Zenless Zone Zero](/docs/zenless-zone-zero).

</Accordion>

## Object folders

Wuthering Waves mods work on **objects**. An object is everything the game draws from one vertex buffer: usually a whole Resonator, sometimes a weapon, a prop or a piece of one Resonator.

When WWMI Tools extracts a frame dump, it makes one folder per object and names it after the object's VB0 hash, for example `93bbbdc0`. The name means nothing to you, so rename the folder to something you can read, like `Aalto`. You can do that here: the hash is also stored inside the folder, in `Metadata.json`.

[Make a frame dump](/docs/wuthering-waves/basics/frame-dump) shows how to get these folders.

The asset repository and most creators name a folder after the Resonator, written in one word with capitals: `Aalto`, `Brant`, `Phoebe`, `Shorekeeper`. Some are not what you would guess, and some Resonators are more than one object:

### Rover

Rover, the player character, is `RoverFemale` or `RoverMale`, one object each. Fix tools and mod pages also write `FRover` and `MRover`, or Rover F and Rover M. Rover changes in many updates, so Rover mods break more often than others.

## Components

Each object is split into numbered **components**. A component is one slice of the object's buffers, drawn with its own set of shaders. Aalto has six components, `Component 0` to `Component 5`. Rover (female) has seven. Changli's outfit has eight.

When you import an object, WWMI Tools makes one collection with one Blender object per component:

<img
  src="/wiki-images/wuthering-waves-basics-character-names-and-parts-2.webp"
  alt="The Blender outliner with a collection named Brant that holds six objects, Component 0 to Component 5"
/>

The numbers do not tell you which part is which, and they differ from one Resonator to the next. To find a part, hide the components one by one in Blender and look.

Three rules come with components:

- **The name needs the word `component` and the number.** WWMI Tools finds each object's component that way, in any case and with any other words around it. `Component 2`, `Hat Component 2` and `component_2 test` all go to component 2. An object without it is not exported.
- **One component can hold several objects.** WWMI Tools merges them at export, and each one still gets its own draw. That is how a mod toggles a hat on and off.
- **Vertex groups are numbers.** Each bone is a vertex group named `0`, `1`, `2` and so on. Keep the numbers of the original model, or the mesh moves with the wrong bones.

Some components, like the head and the shoulders, carry **shape keys** for face expressions and shoulder movement. Keep them, or the face stops moving.

How the vertex group numbers work across components depends on the skeleton mode you pick at import. [Get a model into Blender](/docs/wuthering-waves/models/import-into-blender) explains **Merged** and **Per-Component**.

## Inside an object folder

An extracted folder, and every folder in the asset repository, looks like this:

<Files>
  <Folder name="Aalto (was 93bbbdc0)" defaultOpen>
    <File name="Component 0.ib" />
    <File name="Component 0.vb" />
    <File name="Component 0.fmt" />
    <File name="Component 1.ib, .vb, .fmt: one set per component" />
    <File name="Components-0 t=3dcf2a5e.dds" />
    <File name="Components-0-1-2-3 t=4eba0ca3.dds" />
    <File name="TextureUsage.json" />
    <File name="Metadata.json" />
  </Folder>
</Files>

| File                        | What it is                                                                                                                         |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `Component N.ib`            | The triangle list of one component.                                                                                                |
| `Component N.vb`            | Its vertices: position, normals, bone weights, vertex colors, UVs.                                                                 |
| `Component N.fmt`           | The layout of the vertex data.                                                                                                     |
| `Components-... t=hash.dds` | One texture. The name says which components use it and what its hash is.                                                           |
| `TextureUsage.json`         | Which texture slot (`ps-t0`, `ps-t1` and so on) of each component used which texture hash.                                         |
| `Metadata.json`             | The VB0 hash, the bone data hash, and for each component its index range, vertex count and vertex groups. Also the shape key data. |

<img
  src="/wiki-images/wuthering-waves-basics-character-names-and-parts-1.webp"
  alt="The texture file name Components-0-1-2-3 t=4eba0ca3.dds split into the prefix Components, the components that use it 0-1-2-3, the texture hash t=4eba0ca3 and the file type .dds"
/>

A texture shared by several components appears once, with all their numbers in its name. To find a component's textures, look for its number anywhere in the name: `Components-4` and `Components-0-1-2-3-4` both belong to component 4.

When you edit a texture, keep its file name. The `t=` part is what the exported `mod.ini` matches. [What each texture map does](/docs/wuthering-waves/textures/texture-maps) explains how to tell the diffuse, normal map and light map apart with `TextureUsage.json`.

<Callout type="warning" title="Keep Metadata.json">
  WWMI Tools reads `Metadata.json` when you import, and again at export, where
  the folder is your **Object Sources**. Never delete it or edit it.
</Callout>

## Outfits and alternate forms

Each outfit is its own object, with its own hashes and its own folder. A mod for the default outfit does not change the other outfit, and the other way round. The asset repository marks outfits with `Skin1`: `ChangliSkin1`, `JinshiSkin1`, `SanhuaSkin1`, and `CarlottaSkin1Body` with `CarlottaSkin1HairNormal`.

Some Resonators change shape in a skill or a Liberation form. That form is its own object too. Dump it while it is on screen, and mod it separately.

## Weapons, props and echoes

| Kind    | Folder in the asset repository | Examples                                                               |
| ------- | ------------------------------ | ---------------------------------------------------------------------- |
| Weapons | `WeaponData`                   | `AugustaSword`, `CiacconaStaff`, `IunoDisc`, `LupaSpear`, `ZaniShield` |
| Props   | `MiscellaneousData`            | `BrantCompass`, `CantarellaUmbrella`, `EncorePuppet`, `RoverMask`      |

- **Weapons** usually use one vertex group, `0`. Dump them from the weapon screen and import them with the **Per-Component** skeleton.
- **Props** a Resonator holds are their own objects. Dump the Resonator holding one and you get a second folder for the prop.
- **Echoes**, the monster companions, are objects too, and WWMI Tools can extract and import them.
