You will change the colors of one Resonator's outfit or hair, save the texture the way the game expects, and see it in game. A Resonator is the game's name for a playable character. No 3D editing. WWMI must already load your mods. Written for XXMI Launcher 2.5.0, WWMI 1.1.0 and WWMI Tools 1.8.0 on Wuthering Waves 3.8.

## How a recolor works

Each component of a Resonator uses a few textures. Only the **diffuse** holds the colors you see. WWMI swaps the game's diffuse for your edited copy while your Resonator is on screen. No game file changes.

Wuthering Waves texture files are not named by type. The name tells you which components use the texture and its hash:

| Texture    | How it looks                                           | Edit it for a recolor? |
| ---------- | ------------------------------------------------------ | ---------------------- |
| Diffuse    | A normal colored picture: skin, cloth, patterns        | Yes                    |
| Normal map | The same layout in green, grey or yellowish tones      | No                     |
| Light map  | Like the diffuse, in loud colors such as orange, green | No                     |

All three have names like `Components-3 t=<hash>.dds`. [What each texture map does](/docs/wuthering-waves/textures/texture-maps) shows how to tell them apart for sure, with `TextureUsage.json`.

<Callout type="warning" title="Keep the alpha">
  In a Wuthering Waves diffuse, the alpha channel is not see-through. It holds
  shading data: creators say the game uses it for forced shadows. Lose it and
  the shading on that part looks wrong. The steps below split it off and put it
  back.
</Callout>

## Make the recolor

<Steps>
<Step>

### Get the texture

Pick one route. The paint steps after this are the same for both.

<Tabs items={["Practice on a mod you have", "Make your own mod"]}>

<Tab value="Practice on a mod you have">

The fastest first project. You change a texture inside a mod you downloaded.

1. Open your `Mods` folder: in XXMI Launcher, click the 3-dots button next to **Start**, then **Open Mods Folder**.
2. Copy the mod's whole folder to your desktop as a backup. Never keep the backup inside `Mods`, or both copies load.
3. Open the mod's `Textures` folder and find the diffuse of the part you want. Set Paint.NET as the default app for `.dds` files to see thumbnails in File Explorer.
4. Not sure which file a part uses? Open `mod.ini`, search for the file name, and read the `[ResourceTexture...]` section that loads it.

Keep the result for yourself. The mod is someone else's work, so never share your edited copy.

</Tab>

<Tab value="Make your own mod">

You start from the game's original textures. WWMI Tools writes the `mod.ini` for you, so there is nothing to type.

1. Make a frame dump of your Resonator and extract it with WWMI Tools. [Make a frame dump](/docs/wuthering-waves/basics/frame-dump) shows how.
2. In the **WWMI Tools** sidebar, set **Mode** to **Import Object**. Pick the extracted folder as **Object Sources** and click **Import Object**. Keep the default skeleton, **Merged**.
3. Set **Mode** to **Export Mod**. Pick the imported collection as **Components** and the same extracted folder as **Object Sources**.
4. Set **Mod Folder** to a new folder inside `Mods`, for example `AaltoRecolor`. Leave **Copy Textures** on.
5. Click **Export Mod**.
6. In game, press `F10`. Your mod looks like the original, because nothing is edited yet. Press `F6`: a short distortion shows that your mod is active.

Edit the textures in your mod's `Textures` folder. A new export does not overwrite a texture that is already there under the same name, so your edits stay. If you rename or delete one, the next export copies the original back.

The ready folders in WWMI-Assets stop at game version 2.7, and their texture hashes may not match the current game. Use your own frame dump for a mod that works today. [Export your mod from Blender](/docs/wuthering-waves/models/export-your-mod) explains every export option.

</Tab>

</Tabs>

</Step>
<Step>

### Split off the alpha

Work on a copy: keep a backup of the original `.dds`.

1. Open the `.dds` in Paint.NET.
2. Choose <MenuPath path="Layers > Duplicate Layer" />.
3. With the top layer selected, open <MenuPath path="Adjustments > Modify Channels" />.
4. Set line 1 to `Greyscale`, `Identity`, source `Alpha`. Click `+` and set line 2 to `Alpha`, `Constant`, `255`. Tick `Enabled`, then click **OK**. The top layer now shows the alpha in black and white.
5. Hide the top layer: untick its box in the Layers panel.
6. Select the bottom layer and open **Modify Channels** again. Use one line: `Alpha`, `Constant`, `255`. Now you see every color, with nothing transparent.

{/* NEEDS HANDS-ON TEST: carried over from the shared XXMI workflow, check it on Wuthering Waves: the Modify Channels plugin labels and these two settings in the current Paint.NET 5.x release, on a Wuthering Waves diffuse */}

</Step>
<Step>

### Recolor the part

1. Select the bottom layer and pick the **Magic Wand**. Set **Tolerance** to about 20%, never above 25%.
2. Hold `Shift` and click a color. This selects that color everywhere on the image. Hold `Ctrl` and click to add more colors.
3. Choose <MenuPath path="Adjustments > Black and White" />. Only the selected area turns grey.
4. Choose <MenuPath path="Layers > Add New Layer" />.
5. Pick your new color as the primary color, then press `Backspace` to fill the selection on the new layer.
6. Double-click the new layer and set **Blend mode** to **Overlay**. The grey shading shows through your color.
7. Repeat for each color you want to change.

Use a dark grey instead of pure black: black does nothing in Overlay mode. Select areas that looked empty before, too. The game can show them at the edges.

/>

This English video edits a texture inside a mod the creator already had, the first route above.

</Step>
<Step>

### Put the alpha back

1. Show the alpha layer, select it, then press `Ctrl+A` and `Ctrl+C`.
2. Choose <MenuPath path="Layers > Delete Layer" /> to remove the alpha layer. It stays on your clipboard.
3. Choose <MenuPath path="Image > Flatten" />.
4. Choose <MenuPath path="Effects > Object > Paste Alpha" />. This comes from BoltBait's Plugin Pack.

{/* NEEDS HANDS-ON TEST: carried over from the shared XXMI workflow, check it on Wuthering Waves: the menu location of Paste Alpha from BoltBait's Plugin Pack in the current Paint.NET 5.x release */}

</Step>
<Step>

### Save as DDS

1. Choose <MenuPath path="File > Save As" />. Keep the exact file name, `t=` hash included, and the `.dds` ending.
2. In the DDS window, pick `BC7 (sRGB, DX 11+)`.
3. Tick **Generate Mip Maps**.
4. Click **OK** and replace the old file.

{/* NEEDS HANDS-ON TEST: whether a Wuthering Waves texture saved with mipmaps looks different in game from one with a single mip level, like the dumped originals */}

A few small parts use BC3 or BC1 instead of BC7. [Save DDS textures the right way](/docs/wuthering-waves/textures/save-dds-files) shows how to read the format and explains every option.

</Step>
<Step>

### Test it in game

1. Switch to another Resonator.
2. Press `F10` to reload mods.
3. Switch back and look at your recolor.
4. Hold `F9` to see the original, then let go to compare.
5. Check day and night, indoors, the Resonators menu, combat, and the Resonator from far away.

</Step>
</Steps>

Changed the skin color? Find the face's diffuse in the same folder and recolor it with the same steps and settings. Otherwise the face will not match the body.

## Common problems

<Accordions type="multiple">
<Accordion title="Shading looks wrong or patchy after the recolor" id="wrong-shading">

The alpha was lost or filled. Start again from your backup and paste the alpha back before you save.

</Accordion>
<Accordion title="Colors look washed out, too dark or too strong" id="wrong-colors">

The file was saved in the wrong format. A diffuse must be `BC7 (sRGB, DX 11+)`. Save again.

</Accordion>
<Accordion title="Nothing changed in game" id="nothing-changed">

- Check that the file name is exactly the old one, with the same `t=` hash.
- Turn off other mods for that Resonator: rename their folders so they start with `DISABLED`.
- Check that **LOD Bias** is at **Ultra High**.
- For a downloaded mod, the hash may be out of date since a game update. [Fix your mods after a game update](/docs/wuthering-waves/getting-started/fix-mods-after-an-update) explains what to do.

</Accordion>
<Accordion title="The recolor shows up close, but not far away or in the open world" id="distance">

The game streams lower-detail textures, and they have other hashes. **LOD Bias** at **Ultra High** helps. [Make textures survive game updates](/docs/wuthering-waves/textures/stable-textures) shows the creator side.

</Accordion>
<Accordion title="Another Resonator changed color too" id="shared-texture">

Some textures are shared. Your mod swaps a texture by its hash while your Resonator is on screen, so others on screen that use the same texture change too. Check in `mod.ini` which components use a texture before you edit it.

</Accordion>
<Accordion title="The texture is missing after F10" id="missing-texture">

A typo in the file name, a missing file, or a changed size stops the texture from loading. Keep the original width and height. To see the error text, untick **Mute Warnings** on the **WWMI** tab of the launcher settings.

</Accordion>
</Accordions>

More symptoms and fixes are in [Mods look broken](/docs/wuthering-waves/errors/mods-look-broken).
