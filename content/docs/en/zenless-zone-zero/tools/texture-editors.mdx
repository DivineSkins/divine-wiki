Zenless Zone Zero textures are `.dds` files, most of them compressed as BC7. To edit one, you need an editor that opens DDS and saves it back in the exact same format. This page compares the editors that can, and shows which format each Zenless Zone Zero texture uses.

## The formats Zenless Zone Zero uses

Save every texture in the format of the original. The file name of a dumped texture ends with its format, for example `<hash>-BC7_UNORM_SRGB.dds`. In the save dialogs below, `UNORM_SRGB` means sRGB and `UNORM` means Linear.

An agent part usually has four textures. The asset repo names them after the part, such as `EllenBodyADiffuse.dds`.

| Texture                             | Format           | Pick in Paint.NET           |
| ----------------------------------- | ---------------- | --------------------------- |
| Diffuse (agents and faces)          | `BC7_UNORM_SRGB` | `BC7 (sRGB, DX 11+)`        |
| LightMap                            | `BC7_UNORM`      | `BC7 (Linear, DX 11+)`      |
| MaterialMap                         | `BC7_UNORM`      | `BC7 (Linear, DX 11+)`      |
| NormalMap (agents)                  | `R8G8B8A8_UNORM` | the uncompressed RGBA entry |
| World objects and UI, color texture | `BC7_UNORM_SRGB` | `BC7 (sRGB, DX 11+)`        |

Agent normal maps are not compressed: they are plain 32-bit RGBA files. Some agents also have glow textures (GlowMap, WengineFx) in other formats. If a texture does not fit the table, trust its file name over any rule.

{/* NEEDS HANDS-ON TEST: the exact Paint.NET DDS FileType Plus label for uncompressed R8G8B8A8_UNORM, and the formats of GlowMap and WengineFx textures in a 3.3 dump. */}

Three more rules apply to every editor:

- **Keep the alpha channel.** What the alpha of a Zenless Zone Zero diffuse does is not documented, so keep the original's alpha as it is.
- **Keep the size.** Use the original width and height, in powers of two such as 1024 or 2048.
- **Tick Generate Mip Maps** when you save. The asset repo files have no mipmaps, and both load, but the game's own textures have them.

{/* NEEDS HANDS-ON TEST: whether a missing or present mip chain in a Zenless Zone Zero mod texture changes anything visible in game. */}

On a graphics card with less than 6 GB of video memory, the game uses 1K textures with other hashes. Mods that set textures through SlotFix still work there. Mods that replace textures by hash only cover the size they were made for.

[Save DDS textures the right way](/docs/zenless-zone-zero/textures/save-dds-files) has the full save steps with each dialog.

## Paint.NET (free)

Paint.NET reads and writes DDS files with no extra install. Its DDS support, DDS FileType Plus, has been built in since Paint.NET 4.2.2.

When you save as `.dds`, a **Save Configuration** window opens:

<img
  src="/wiki-images/zenless-zone-zero-tools-texture-editors-1.webp"
  alt="The Paint.NET DDS Save Configuration window, with the format list at the top, compression speed, error metric, and the Generate Mip Maps checkbox"
/>

1. Open the format list at the top. It shows `BC1 (Linear, DXT1)` in this picture.
2. Pick the entry from the table above.
3. Tick **Generate Mip Maps**.
4. Finish the save.

To protect the alpha while you recolor, creators split it off and paste it back with free Paint.NET plugins such as `Modify Channels` or `Alpha Mask Import`. [Your first mod: recolor a character](/docs/zenless-zone-zero/textures/recolor-a-character) shows how.

## Photoshop (paid)

Photoshop needs a DDS plugin. Two work:

- **Intel Texture Works 1.0.4.** Free, but Intel archived it in 2023 and it is no longer updated. Creators still use it. Put `IntelTextureWorks.8bi` in Photoshop's `Required\Plug-Ins\File Formats` folder. When you open a DDS, tick **Load Transparency as Alpha Channel**, or you lose the alpha.
- **NVIDIA Texture Tools Exporter.** Free with an NVIDIA account. It works as a Photoshop plugin and as a separate app.

{/* NEEDS HANDS-ON TEST: whether NVIDIA Texture Tools Exporter sets the sRGB flag on BC7 files today, and the exact Intel Texture Works label for the BC7 sRGB option. */}

## GIMP and Krita (free)

- **GIMP 3.2** can export BC7. It is not known if it marks the file as sRGB, which diffuse textures need. Check your result in game, or export a PNG and convert it with texconv.
- **Krita** has no built-in BC7 export. Export a PNG and convert it with texconv.

## texconv (command line)

texconv is Microsoft's free command-line converter, part of DirectXTex. It turns a PNG into a DDS in the exact format you name. Use it with any editor that saves PNG. Download `texconv.exe` from the [DirectXTex releases page](https://github.com/microsoft/DirectXTex/releases).

```text
texconv.exe -f BC7_UNORM_SRGB -m 0 -sepalpha -y EllenBodyADiffuse.png
texconv.exe -f BC7_UNORM -m 0 -sepalpha -y EllenBodyALightMap.png
```

| Flag                                  | What it does                                                                                                           |
| ------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `-f BC7_UNORM_SRGB` or `-f BC7_UNORM` | The output format. Copy it from the original's file name.                                                              |
| `-m 0`                                | Makes the full mipmap chain. `-m 1` makes none.                                                                        |
| `-sepalpha`                           | Treats alpha as separate data, so the alpha stays clean.                                                               |
| `-vflip`                              | Flips the image. Dumped textures are upside down compared with normal pictures, so flip outside art before you use it. |
| `-y`                                  | Overwrites an existing file.                                                                                           |

{/* NEEDS HANDS-ON TEST: the texconv lines above on a Zenless Zone Zero 3.3 diffuse and light map, checking that colors match the original in game. */}

texconv's sister tool, texassemble, builds texture arrays for animated textures.

## Common problems

<Accordions type="multiple">
<Accordion title="The colors look wrong in game" id="wrong-colors">

The texture was saved in the wrong format. A diffuse texture must be BC7 sRGB. Check the original's file name and save again.

</Accordion>
<Accordion title="Shading or shine looks wrong after an edit" id="wrong-shading">

A LightMap or MaterialMap was probably saved as sRGB. They hold data, not colors, so they must be BC7 Linear. Save them again with `BC7 (Linear, DX 11+)`.

{/* NEEDS HANDS-ON TEST: what a LightMap or MaterialMap saved as BC7 sRGB looks like in game. The symptom above is expected from how sRGB works, not seen in a source. */}

</Accordion>
<Accordion title="My new normal map does not show" id="normal-map">

Normal maps cannot be replaced by hash since Zenless Zone Zero 1.3. Set them through SlotFix with a `Resource\ZZMI\NormalMap = ref ...` line in the part's section, the way XXMI Tools writes it.

</Accordion>
<Accordion title="Yellow error text and the texture does not show" id="yellow-error">

The size is not a power of two, or the file name does not match the `.ini`. Keep the original size and name.

</Accordion>
<Accordion title="The texture looks darker in another program" id="darker">

Some viewers handle the sRGB flag differently. Judge the colors in game, not in the viewer.

</Accordion>
</Accordions>

More symptoms are on [Mods look broken](/docs/zenless-zone-zero/errors/mods-look-broken).
