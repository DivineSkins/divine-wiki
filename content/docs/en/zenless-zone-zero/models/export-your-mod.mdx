<LevelPill level="intermediate" />

Export turns your Blender scene into a mod folder that ZZMI loads. Most failed exports break one of a few rules about names and mesh data. This page lists those rules, then runs the export. Written for XXMI Tools 1.8.2 on Blender 4.5 LTS and ZZMI 1.5.2.

<Accordions>
<Accordion title="Coming from another game?">

- **Genshin Impact:** same add-on, with the `Genshin Impact` preset and other axes. Its template writes `Resource\GIMI\...` lines and has no `DRAW_TYPE` split. See the [Genshin Impact section](/docs/genshin-impact).
- **Honkai: Star Rail:** same add-on, with the `Honkai Star Rail` preset. Its template writes a compute-skinning `.ini` and binds textures with `this =` per texture hash. See the [Honkai: Star Rail section](/docs/honkai-star-rail).
- **Wuthering Waves:** a different add-on, WWMI Tools. It exports straight into `WWMI\Mods`, uses `component N` names and a merged skeleton, and writes the whole `mod.ini`. See the [Wuthering Waves section](/docs/wuthering-waves).
- **Deadlock or League of Legends:** nothing is packed or compiled. XXMI Tools writes buffers and an `.ini`, ZZMI swaps them in while the game draws, and `F10` reloads them.

</Accordion>
</Accordions>

## Check these rules before you export

### Names

<img
  src="/wiki-images/zenless-zone-zero-models-export-your-mod-1.webp"
  alt="The dump folder name Ellen plus the component Hair and part A from hash.json gives the object name EllenHairA. One visible object named EllenHairA or EllenHairA-2 exports, and a hidden EllenHairA.001 is skipped. EllenHair-A, HairA, EllenHairA and EllenHairA.001 both visible, or a folder renamed to Ellen_v2 fail"
/>

- **Every object name starts with folder, component and part.** Ellen's parts are `EllenHairA` and `EllenBodyA`. Belle's body has two parts, `BelleBodyA` and `BelleBodyB`. The names come from `hash.json`.
- **One visible object per part.** Two visible objects that start with the same part name stop the export. Hide or rename spare meshes.
- **Several meshes in one part.** Make a collection whose name starts with the part name, for example `EllenBodyA`, and put your meshes in it. Keep the emptied original object in the scene, outside the collection. Export merges the collection into that part and writes one `drawindexed` line per object, ready for a toggle.

{/* NEEDS HANDS-ON TEST: with XXMI Tools 1.8.2, that the emptied original object may sit outside the part's collection, and that each object in the collection gets its own commented drawindexed line */}

- **Keep every part of a component you export.** A part you do not want stays as an empty object. Components you did not touch can be left out. Older guides tell you to edit `hash.json`: you no longer need to.

{/* NEEDS HANDS-ON TEST: that XXMI Tools 1.8.2 exports a Zenless Zone Zero agent with one untouched component left out of the scene, and fails with "Cannot find object" when one part of an exported component is deleted */}

### Build on the imported objects

Never export an object you made from scratch. The imported objects carry hidden `3DMigoto:` properties that export needs. To put your own mesh into a part:

1. Line up your mesh with the original. Select it and press `Ctrl+A`, then choose **All Transforms**.
2. Select the imported part object, press `Tab`, press `A`, then `X` and choose **Vertices**. Press `Tab` again. The object is now empty.
3. Click your mesh, then `Shift`+click the emptied part object, so it is selected last.
4. Press `Ctrl+J`. Your mesh joins into the part object and keeps its name and properties.

An object without these properties stops the export with `... is missing custom properties required for export!`. Import the dump again and join your mesh into the new import.

### Vertex groups

Vertex groups are the game's bone numbers. Export reads each group's place in the list, not its name, so the list must run `0`, `1`, `2` ... in order, with no gaps. A missing number shifts every bone after it.

Before every export, open the **XXMI Toolbox** panel in the XXMI Tools sidebar and click:

1. **Merge shared name Vertex Groups**. It folds `12.001` into `12`.
2. **Fill gaps in Vertex Groups**. It adds empty groups for missing numbers and sorts the list.

Hold `Alt` while you click to run a button on every selected object. If you used **Remove unused Vertex Groups**, always run **Fill gaps** after it.

Every vertex of a moving part needs weight. Only 4 weights per vertex fit, and **Normalize weights to format** trims extras at export. [Weight paint a mesh](/docs/zenless-zone-zero/models/weight-painting) covers weights in full.

{/* NEEDS HANDS-ON TEST: carried over from the shared XXMI workflow, check on a Zenless Zone Zero agent that a gap in the vertex group list breaks the mesh in game and that Merge and Fill gaps fix it */}

### UV maps and COLOR

- **UV maps** keep the original names, `TEXCOORD.xy` to `TEXCOORD3.xy`, in capitals. When you join pieces, every piece needs the same UV map names. Otherwise Blender adds an extra map, and textures can go blank. **Clean UV Names** in the toolbox renames maps by their order.
- **A `COLOR` attribute** must exist on every exported object, with domain `Face Corner` and type `Byte Color`. Copy its values from the original with a Data Transfer modifier. [UV maps, vertex colors, and outlines](/docs/zenless-zone-zero/models/uvs-and-vertex-colors) shows how.

### Size

Stay close to the original vertex count. Very heavy meshes, with hundreds of thousands of vertices, cost performance. The exported `.ini` raises the game's vertex limit for you. Each part keeps one set of four textures, at the size of the original.

## Export the mod

<Steps>
<Step>

### Fill in the XXMI Tools panel

1. Press `N` in the 3D Viewport and open the **XXMI Tools** tab.
2. Check **Dump Folder**. It is the folder you imported from, the one with `hash.json`. Import fills it in.
3. Set **Output Folder** to a new, empty folder. It must not be the dump folder. A folder inside `%AppData%\XXMI Launcher\ZZMI\Mods` makes testing faster.
4. Check that **Game to mod** says `Zenless Zone Zero`.

If you leave **Output Folder** empty, the mod goes to `<DumpName>Mod` next to the dump, for example `EllenMod`.

{/* SCREENSHOT: zenless-zone-zero-models-export-your-mod-2.webp, Blender 4.5 sidebar with the XXMI Tools v1.8.2 tab open, Dump Folder and Output Folder filled in, Game to mod set to Zenless Zone Zero, and the Export Settings panel unfolded with the three outline options visible */}

</Step>
<Step>

### Check the export settings

Unfold **Export Settings**. The defaults suit a first export:

| Setting                           | Default | What to know                                                                                                 |
| --------------------------------- | ------- | ------------------------------------------------------------------------------------------------------------ |
| **Ignore hidden objects**         | on      | Hidden objects are skipped. Keep reference copies hidden.                                                    |
| **Apply modifiers and shapekeys** | on      | Modifiers apply on a copy. Your scene stays as it is.                                                        |
| **Normalize weights to format**   | on      | Keeps at most 4 weights per vertex.                                                                          |
| **Mod textures**                  | on      | Copies the original textures once. It never overwrites a file with the same name.                            |
| **Write buffers**, **Write ini**  | on      | Write the mesh files and the `.ini`.                                                                         |
| **Outline Optimization**          | on      | Rebuilds the outline data in `TEXCOORD1.xy`. It is slow, so some creators turn it off until the last export. |
| **Outline gate divergence**       | `10.0`  | Only for Zenless Zone Zero. Below this angle the outline data is set to zero, like the game does.            |
| **Credit**                        | empty   | Your name. The game shows "Created by" with it when the mod loads.                                           |

Keep **Outline Optimization** on with XXMI Tools 1.8.2. Switch it off if outlines or shading look wrong. Guides from before mid-2025 say off: that applied to older versions.

{/* NEEDS HANDS-ON TEST: export one Zenless Zone Zero agent with Outline Optimization on and off in XXMI Tools 1.8.2 and compare outlines and shading in game */}

Older guides and videos show other options, such as **Copy textures**, **Use foldername when exporting** and **Join meshes**. Those came from earlier versions. In 1.8.2, **Mod textures** does the job of **Copy textures**, and the other two are gone. For mesh toggles, use a collection per part instead of **Join meshes**. The XXMI Tools page, linked under What you need, explains every other option.

</Step>
<Step>

### Click Export Mod

Click **Export Mod** at the bottom of the panel. When it works, the status bar says `Exported <Name> to <folder> in <n> seconds`.

Errors and warnings show in the status bar. For the full text, open <MenuPath path="Window > Toggle System Console" />.

</Step>
<Step>

### Test it in game

1. Copy the mod folder into `%AppData%\XXMI Launcher\ZZMI\Mods`, unless you exported straight into it.
2. Turn off any other mod for the same agent or outfit.
3. Switch to another agent, press `F10` to reload, then switch back.
4. Check the mod in the agent screen, then while running and attacking.

[Test and reload your mod](/docs/zenless-zone-zero/basics/test-your-mod) explains the keys and on-screen warnings.

</Step>
</Steps>

## What the export writes

<Files>
  <Folder name="EllenMod" defaultOpen>
    <File name="Ellen.ini: the mod's instructions for ZZMI" />
    <File name="EllenHairPosition.buf: vertex positions, normals, tangents" />
    <File name="EllenHairBlend.buf: bone weights" />
    <File name="EllenHairTexcoord.buf: COLOR and the four UV maps" />
    <File name="EllenHairA.ib: one index file per part" />
    <File name="EllenBodyPosition.buf, EllenBodyBlend.buf, EllenBodyTexcoord.buf" />
    <File name="EllenBodyA.ib" />
    <File name="EllenHairADiffuse.dds, NormalMap, LightMap, MaterialMap" />
    <File name="EllenBodyADiffuse.dds, NormalMap, LightMap, MaterialMap" />
  </Folder>
</Files>

{/* NEEDS HANDS-ON TEST: the exact file names XXMI Tools 1.8.2 writes for Ellen */}

Each component gets its own set of `.buf` files, and each part its own `.ib` file. The `.ini` hooks the mesh by its **Blend** hash, never the Position hash: some agents and outfits share a Position hash, so a mod on it would show on both. Each component gets a section like this:

```ini
[TextureOverrideEllenHairBlend]
hash = <blend hash>
handling = skip
if DRAW_TYPE == 2 || DRAW_TYPE == 4
    vb1 = ResourceEllenHairTexcoord
    vb2 = ResourceEllenHairBlend
    checktextureoverride = ib
elif DRAW_TYPE == 1
    vb0 = ResourceEllenHairPosition
    vb2 = ResourceEllenHairBlend
    Draw = <vertex count>, 0
endif
```

Each part gets a section like this. It matches the part by its IB hash, first index and index count, then hands the four textures to SlotFix:

```ini
[TextureOverrideEllenHairA]
hash = <ib hash>
match_first_index = 0
match_index_count = <index count>
handling = skip
ib = ResourceEllenHairAIB
Resource\ZZMI\Diffuse = ref ResourceEllenHairADiffuse
Resource\ZZMI\NormalMap = ref ResourceEllenHairANormalMap
Resource\ZZMI\LightMap = ref ResourceEllenHairALightMap
Resource\ZZMI\MaterialMap = ref ResourceEllenHairAMaterialMap
run = CommandList\ZZMI\SetTextures
drawindexed = <index count>, <offset>, 0
```

SlotFix ships inside ZZMI. Never copy SlotFix or RabbitFX into your mod. A mod folder also never holds `d3dx.ini`, `d3d11.dll` or a `ShaderFixes` folder. [How a mod .ini works](/docs/zenless-zone-zero/ini/how-a-mod-ini-works) explains each line.

## Export again, faster

- **Export straight into `Mods`.** Then each export is one `F10` away from a test.
- **Hand-edited the `.ini`?** Back it up and untick **Write ini**. Later exports then refresh only the mesh files. If the vertex count changes, tick it again, because the counts live in the `.ini`, and copy your edits back in.
- **Before you share,** delete textures you did not change, with their lines in the `.ini`. Unchanged textures make the download bigger and break when an update changes them.
- **Leave out what you did not change.** A body mod should not touch the hair or face. Then it still works next to a hair mod for the same agent.

Need to replace only one buffer, for example the UVs? XXMI Buffer Export by failsafe65 adds **Position**, **Blend**, **Texcoord** and **IB** buttons to the XXMI Tools panel. It is new (2026) and was not tested for this guide. It fails when parts share vertices. A normal export is simpler when the vertex count or order changes.

## Common problems

<Accordions type="multiple">
<Accordion title='"Please select a valid game before continuing."' id="select-game">

**Game to mod** is empty. Set it to `Zenless Zone Zero` in the sidebar, then export again.

</Accordion>
<Accordion title='"Cannot find match for name"' id="no-match-for-name">

The dump folder was renamed, or no object name starts with the folder name. Rename the folder back to the agent name its files use, such as `Ellen`, and keep object names starting with it.

</Accordion>
<Accordion title='"Hash file ... does not exist or is not a file"' id="no-hash-json">

**Dump Folder** points to the wrong place, such as a mod folder or a `FrameAnalysis` folder. Point it to the extracted dump folder with `hash.json`. If `hash.json` is gone, download or extract the folder again.

</Accordion>
<Accordion title='"Cannot find object ... in the scene"' id="missing-part">

A part of a component you export has no object. It was deleted, renamed, or hidden while **Ignore hidden objects** is on. Bring the object back. It may be empty.

</Accordion>
<Accordion title='"Found multiple objects with the name ..."' id="multiple-objects">

Two visible objects start with the same part name, such as `EllenHairA` and `EllenHairA.001`. Hide or rename one, or put both in a collection named after the part.

</Accordion>
<Accordion title='"... is missing the following UV layers" or "vertex colors: COLOR"' id="missing-uv-or-color">

A UV map is missing or has the wrong name, or the `COLOR` attribute is missing. Rename the UV maps with **Clean UV Names**. Add `COLOR` with domain `Face Corner` and type `Byte Color`, then copy the values from the original.

</Accordion>
<Accordion title="The export works, but parts stretch or fly off in game" id="stretching">

The vertex groups have a gap or are out of order. Run **Merge shared name Vertex Groups** and **Fill gaps in Vertex Groups**, export again, and press `F10`. [Model problems in game](/docs/zenless-zone-zero/errors/model-problems) covers more symptoms.

</Accordion>
<Accordion title="Outlines or shading look wrong across the whole mesh" id="outlines-broken">

Export again with **Outline Optimization** off and compare. If your mesh is new, also check its `TEXCOORD1.xy` and `COLOR` values.

</Accordion>
</Accordions>

Every export and import message is listed on [Blender export and import errors](/docs/zenless-zone-zero/errors/creator-errors).
