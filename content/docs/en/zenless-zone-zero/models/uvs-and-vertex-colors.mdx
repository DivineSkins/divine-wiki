<LevelPill level="intermediate" />

Every mesh you export needs four UV maps with the right names and a `COLOR` attribute with sensible values. In Zenless Zone Zero, the first UV map places the texture, the second holds outline data, and `COLOR` controls outline thickness and hair shadows. Get them wrong and the part turns blank, shades oddly, or gets thick outlines. Written for XXMI Tools 1.8.2 on Blender 4.5 LTS.

## What Zenless Zone Zero reads

| Data          | Name in Blender                      | What the game uses it for                                                                        |
| ------------- | ------------------------------------ | ------------------------------------------------------------------------------------------------ |
| First UV map  | `TEXCOORD.xy`                        | Where the texture goes.                                                                          |
| Second UV map | `TEXCOORD1.xy`                       | Outline data: the direction the outline pushes out, values from -1 to 1. Not a texture layout.   |
| Third UV map  | `TEXCOORD2.xy`                       | A projection of the model that some effects use.                                                 |
| Fourth UV map | `TEXCOORD3.xy`                       | Like the first, but can map the inner side of a mesh, like a skirt's underside, to another area. |
| Vertex color  | `COLOR`, `Face Corner`, `Byte Color` | Red is outline thickness. Blue is hair shadow. See the table below.                              |
| Normals       | the mesh's own normals               | Lighting, and the outline data that export builds.                                               |

The names are case-sensitive. Compare your mesh with the original part in the **Object Data** tab (the green triangle). The screenshot comes from an older importer, so its object names end with the file name.

These meanings come from community research on an early version of the game, and some are unsure. When you are unsure, keep the original's values.

## UV maps

### Name them right

1. Give a new mesh all four UV maps. The easiest way: join it into the original part for a moment with `Ctrl+J`, then separate it again with `P` > **Selection**. It keeps the part's UV maps, vertex groups and `COLOR`.
2. Make sure every piece you will join has the same four UV map names. If the names differ, `Ctrl+J` adds an extra map that the game ignores, and the texture goes blank.
3. Delete UV maps the part does not need.
4. Or let XXMI Tools rename them: press `N`, open **XXMI Tools** > **XXMI Toolbox**, and click **Clean UV Names**. It renames the maps by their order: `TEXCOORD.xy`, `TEXCOORD1.xy`, and so on.

### Fix TEXCOORD1 on new mesh

`TEXCOORD1.xy` is outline data, not a texture layout. On a new mesh it holds random values, and the mesh shades differently from the rest of the agent. Two fixes:

- **Let export write it.** Keep **Outline Optimization** on. It rebuilds `TEXCOORD1.xy` from the mesh's normals on every export.
- **Set it to zero.** Select the new mesh's faces, pick `TEXCOORD1.xy` in **UV Maps**, unwrap it, then scale all its UVs to the top-left corner, point `0, 0`.

`TEXCOORD2.xy` is a projection that some effects use. XXMI Tools no longer makes it for you. On new mesh, no current guide gives exact steps: compare it with the original's map in the UV Editor, and keep the original's where you can.

### Fit several materials into one texture

Each part draws with one set of four textures: `Diffuse`, `NormalMap`, `LightMap` and `MaterialMap`. Check the dump's `hash.json` to see which part uses which texture. A new model with several materials must share one texture set per part, called an atlas. Keep every texture the same size as the original.

1. Build the atlas image in your texture editor. Four 1024 blocks make one 2048 image. Do not go bigger than the original.
2. In Blender's UV Editor, set **Pivot Point** to **2D Cursor** and put the cursor at `0, 0`. Turn **UV Sync Selection** off.
3. In the 3D Viewport, select the faces of one material. Hover over the UV Editor and press `A`.
4. Type `S` `0.5` and press `Enter`. The UVs shrink to one corner block.
5. Move them by exact steps: `G` `Y` `0.5` for the top-left block, `G` `X` `0.5` for the bottom-right. For the top-right, do both. Never move blocks by eye.
6. For a 4 by 4 grid, scale by `0.25` and move in steps of `0.25`.

Make the NormalMap, LightMap and MaterialMap atlases with the same layout. [Save DDS textures the right way](/docs/zenless-zone-zero/textures/save-dds-files) covers the formats.

A piece with its own textures does not need an atlas. In this game the `.ini` can give each mesh in a part its own texture set. [Add or swap clothing parts](/docs/zenless-zone-zero/models/add-clothing-parts) shows how.

### When your UVs change

The part's other textures still follow the old layout. Fix each one, in the part's section of the `.ini`:

- **Glow in the wrong place.** Make new `GlowMap` or `WengineFx` textures for the new layout, or hide the glow: `Resource\ZZMI\GlowMap = ref Resource\ZZMI\EmptyGlowMap`.
- **The normal map no longer fits.** Point it at the flat one that ships with ZZMI: `Resource\ZZMI\NormalMap = ref Resource\ZZMI\FlatNormalMap`.

## Vertex colors

<Callout type="warning" title="Type hex values, not numbers">
  In Blender's color picker, `0.5` and hex `80` are not the same. A typed `0.5`
  is stored as about `BC`, so the values stop matching the original. Always type
  the hex value, like `808000`. The alpha slider has no hex field, but it is not
  converted: `0.502` on that slider is `80`.
</Callout>

### Copy the colors from the original

This is the best way. Do it before you join your mesh into the original part.

1. Select your mesh. In **Object Data** > **Color Attributes**, check for a `COLOR` attribute. If there is none, click `+` and set **Name** `COLOR`, **Domain** `Face Corner`, **Data Type** `Byte Color`.
2. Add a **Data Transfer** modifier. Set **Source** to the hidden copy of the original part.
3. Tick **Face Corner Data** and pick **Colors**.
4. Leave **Layer Selection** on `All Layers` and **Layer Mapping** on `By Name`.
5. Apply the modifier.
6. Check the result with the node setup below, next to the original.

Outlines too thick on an edited part? Copy the colors the same way from a part whose outline still looks right.

{/* NEEDS HANDS-ON TEST: the Face Corner Data option label (Colors or Color Attributes) in the Blender 4.5 Data Transfer modifier. */}

### See one channel at a time

Each channel means something different, so view them one by one:

1. Open the **Shading** workspace and give the part a new material.
2. Add an **Attribute** node with **Name** `COLOR`.
3. Add a **Separate Color** node and connect the Attribute node's **Color** to it.
4. Connect **Red** (or **Green**, **Blue**) to the **Surface** of the **Material Output**.
5. Look at the part in Material Preview. Light areas are high values, dark areas low.

### Values creators use

These meanings are community findings, not official. When you are unsure, keep the original's values.

| Channel | What it does                             | Value                                                               |
| ------- | ---------------------------------------- | ------------------------------------------------------------------- |
| R       | Outline thickness. Thinner at hair tips. | A flat mid-grey, `80`. Change it only for thinner or thicker lines. |
| G       | Not known. Maybe outline depth.          | Keep mid-grey, `80`.                                                |
| B       | Hair shadow and contact shadow           | `00` on body and clothing. On hair, keep the original's.            |
| A       | Something around the neck                | Not known. Keep the original's, and keep the original neck mesh.    |

For a new piece of clothing with no original under it, that gives `808000`. Copy the alpha from a nearby original part.

XXMI Tools has a **Reset Vertex Colors** button that sets one flat color. Its default suits other games: it sets red to full, not the mid-grey this game uses. Type the values by hand instead.

## Normals and outlines

Normals light the mesh and shape the outline. Check them before every export.

1. Turn on the **Face Orientation** overlay. Blue faces point out, red faces point in.
2. Press `Ctrl+A` > **All Transforms** first, then check again.
3. Select red faces and press `Alt+N` > **Flip**, or use **Recalculate Outside**.

If the mesh looks faceted after an edit, merge with `M` > **By Distance** and tick **Sharp Edges**, so hard edges stay hard. On a dented area, use <MenuPath path="Mesh > Normals > Smooth Vectors" />. Old guides tell you to use **Auto Smooth**. Blender 4.1 removed it, so skip those steps.

On export, **Outline Optimization** joins the normals of vertices in the same place, turns them into outline data, and writes it to `TEXCOORD1.xy`. Where the outline would follow the normal anyway, it writes zero. These export settings control it:

| Setting                                | Default | What it does                                                                       |
| -------------------------------------- | ------- | ---------------------------------------------------------------------------------- |
| **Outline Optimization**               | on      | Rebuilds the outline data. Slow, so some creators turn it off while testing.       |
| **Outline decimal rounding precision** | `8`     | How close vertices must be to share one outline vertex.                            |
| **Outline gate divergence**            | `10.0`  | Below this angle, in degrees, the outline data is set to zero, like the game does. |
| **Use custom normals for outlines**    | off     | Builds the outline from your own split normals instead.                            |

Keep **Outline Optimization** on with XXMI Tools 1.8.2. Switch it off if outlines or shading look wrong. Guides from before mid-2025 say off: that applied to older versions.

## Common problems

<Accordions type="multiple">
<Accordion title="The texture is blank, white, or flat on a joined piece" id="blank-texture">

The pieces had different UV map names when you joined them. Rename every piece's maps to `TEXCOORD.xy` to `TEXCOORD3.xy` before `Ctrl+J`, or run **Clean UV Names**.

</Accordion>
<Accordion title="The texture is scrambled" id="scrambled-texture">

The first UV map is not named `TEXCOORD.xy`, or some faces are flipped. Fix the name and the normals, then export again.

</Accordion>
<Accordion title="New mesh shades differently from the rest" id="new-mesh-shading">

Its `TEXCOORD1.xy` holds random values. Export with **Outline Optimization** on, or scale that UV map to `0, 0` as shown above.

</Accordion>
<Accordion title="Outlines and shading look wrong across the whole mesh" id="whole-mesh-shading">

Export again with **Outline Optimization** off and compare. Older versions of XXMI Tools broke this game's outlines with it on.

</Accordion>
<Accordion title="Outlines are thick or blotchy" id="thick-outlines">

The `COLOR` red channel is too high or uneven. Copy the colors from a part whose outline looks right.

</Accordion>
<Accordion title="Dark patches on the body" id="dark-patches">

The `COLOR` blue channel is not `00` on a body part. Blue adds hair and contact shadow. Copy the colors from the original body part.

</Accordion>
</Accordions>

More symptoms are on [Model problems in game](/docs/zenless-zone-zero/errors/model-problems).
