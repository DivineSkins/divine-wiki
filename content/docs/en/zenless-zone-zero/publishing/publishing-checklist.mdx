Your mod works in your game. This checklist turns it into an archive that works for every player who downloads it, credits everyone it builds on, and follows the community's rules. Written for XXMI Launcher 2.5.0, ZZMI 1.5.2 and Zenless Zone Zero 3.3.

## The checklist

Work through it top to bottom. Each part has its own section below.

1. The folder holds only what the mod needs.
2. The `.ini` works on any player's setup.
3. A readme says how to install and use the mod, and what it needs.
4. Two or more preview shots show the mod in game, with your UID hidden.
5. Everyone whose work you used is credited, and asked first.
6. The mod is fair to share.
7. The archive opens without a password and holds one top folder.
8. You tested the archive itself, as a player would.

## Clean the mod folder

<img
  src="/wiki-images/zenless-zone-zero-publishing-publishing-checklist-1.webp"
  alt="A mod archive with one top folder EllenMod holding the .ini, buffers, changed textures, a readme and an optional preview. d3dx.ini, d3d11.dll, SlotFix, TTLib, the HP library, RabbitFX, a ShaderFixes folder, programs, the .blend file and the dump folder are marked to leave out"
/>

1. **Use one top folder, named after the mod,** such as `EllenMod`. A player drops that folder into `Mods` and is done.
2. **Keep only mod files:** the `.ini`, the `.buf` and `.ib` files from the export, the `.dds` textures the `.ini` uses, and `.hlsl` files only if your mod uses them. A readme and preview images are fine too.
3. **Leave out textures you did not change,** with their lines in the `.ini`. They make the download bigger and break when an update changes them.
4. **Start no file or folder name with `DISABLED`.** ZZMI skips anything named that way, so that part of your mod would never load.
5. **Remove manager changes.** No Reload Mod Manager writes lines into mod `.ini` files. Run its **Restorer** before you share. Other managers may change keys, so check the `.ini` by eye.

### What never goes in a mod

| File                                            | Why                                                                                                                          |
| ----------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `d3dx.ini`                                      | XXMI Launcher refuses to start with it in `Mods`: `Cannot start with d3dx.ini in Mods folder!`                               |
| `d3d11.dll` or any other `.dll`                 | The launcher brings its own. A `.dll` in a mod is a sign of malware.                                                         |
| A copy of SlotFix, TTLib or the HP library      | ZZMI ships these in `ZZMI\Core\ZZMI\Libraries`. A second copy conflicts with it, and the launcher offers to turn it off.     |
| RabbitFX                                        | Players keep exactly one copy in their whole `Mods` folder. Two copies crash the game. Name it in your readme instead.       |
| A `ShaderFixes` folder                          | ZZMI keeps its own files there. Package shader edits as a normal mod, with `[ShaderOverride]` and `[CustomShader]` sections. |
| `.exe`, `.bat` or any other program             | A mod is data only. Players are taught to treat programs in a mod as malware.                                                |
| Your `.blend` file and the original dump folder | They hold the game's own model data. Keep them for yourself, never share them publicly.                                      |

## Check the .ini

A mod that works for you can still misbehave next to other players' mods, or break on the next update. Open your `.ini` in a text editor and check:

- **Every key only reacts on screen.** Each key section needs `condition = $active == 1`. Without it, the key also fires when your agent is not on screen, and flips other mods that use the same key. XXMI Tools writes `$active` only when you fill in **Credit** at export.
- **Toggles are remembered.** Toggle values need `global persist` in `[Constants]`, so ZZMI keeps them between sessions.
- **Your keys stay clear of ZZMI's own.** ZZMI uses `F6`, `F8`, `F9`, `F10` and `F12`, plus `Ctrl+F9`, `Ctrl+F12` and `Ctrl+Alt+F10`. Arrow keys with modifiers work on every keyboard layout. Write the modifiers you do not want as `NO_` words.
- **Textures go through SlotFix.** Each part sets `Resource\ZZMI\...` lines, then `run = CommandList\ZZMI\SetTextures`. No texture hash sections, and any `run = CommandListSkinTexture` sits inside `if 0 == 1` and `endif`. Then the mod also works on graphics cards with less than 6 GB of video memory.
- **The mesh follows the Blend hash,** as XXMI Tools writes it. A mod on a Position hash can also show on another agent.
- **Sections cover only what you changed.** A body mod should not touch the hair or face, so it still works next to a hair mod for the same agent.
- **`handling = skip` sits in a part section** with both `match_first_index` and `match_index_count`. On a section with only the IB hash, it can make the sky glitch.
- **Comments sit on their own line.** A `;` after a value, such as `hash = 1234abcd ; glasses`, breaks that line.
- **No global `CheckTextureOverride` in a `[ShaderRegex]` section.** XXMI Launcher's Mod Optimizer switches it off because it slows every player's game.
- **The file is saved as UTF-8.**

```ini
[KeyGlasses]
key = CTRL NO_SHIFT NO_ALT VK_UP
condition = $active == 1
type = cycle
$glasses = 0,1
```

[How a mod .ini works](/docs/zenless-zone-zero/ini/how-a-mod-ini-works) explains each of these lines.

## Write a readme

Add a `README.txt` to the top folder. Players read it before they ask you questions. Copy this and fill it in:

```text
<Mod name>
<One line: what it changes, on which agent and outfit.>

Install
1. Extract this archive.
2. Put the <ModFolder> folder in %AppData%\XXMI Launcher\ZZMI\Mods
3. In game, switch to another agent, press F10, and switch back.

Game settings
Run the game in DirectX 11.
Settings > Graphics: Character Quality = High,
High-Precision Character Animation = Disable.

Keys
<key>   <what it does>

Requires
XXMI Launcher with ZZMI 1.5.2 or newer
(https://github.com/SpectrumQT/XXMI-Launcher/releases)
RabbitFX (only if your mod uses it: keep one copy in Mods)
Tested on Zenless Zone Zero 3.3

Known issues
<Anything that still looks wrong, and any workaround.>

Credits
<Name>: <role, such as model, textures, testing>
Original character design: HoYoverse

Changes
v1.0 (Zenless Zone Zero 3.3): first release
```

- **Requirements:** name XXMI Launcher and the ZZMI version you tested with. SlotFix, TTLib and the HP library come with ZZMI, so players need nothing else for them. If your mod uses RabbitFX, name it here and remind players to keep one copy only. Delete the RabbitFX line if your mod does not use it.
- **Outfits:** say which outfit the mod is for. A mod for an agent's default look does not show on an outfit, and the other way round.
- **Game version:** players use it to tell whether your mod may need a fix after an update.

## Take preview shots

- **Show the mod in game,** at least two shots: for example the front in the agent screen and the mod in motion.
- **Hide or crop your UID** in every screenshot and video. A Hide UID mod is optional, for privacy.
- **Keep the shots clean.** This wiki covers mods anyone can look at: no suggestive poses or camera angles.
- **Keep modded shots off official channels.** The official Discord, HoYoLAB and official subreddits remove modded content. In 2025 a player was banned from the official Zenless Zone Zero Discord for posting a modded screenshot with the UID visible.

## Credit everyone

- **List everyone who worked on the mod,** with their role: model, textures, `.ini`, testing.
- **Name the original designer.** The agent belongs to HoYoverse. Say so in the credits.
- **Ask before you reuse parts of someone's mod,** such as a hairstyle, a texture or a toggle setup. Credit them, even when they say yes.
- **Ask before you combine other people's mods** into a merged mod that you share.
- **Use your own work, or parts you have permission for.** Do not port models from other games, films or anime.

## Keep it fair

<Callout type="warning" title="Fan work, not a product">
  HoYoverse's terms allow no commercial use of its characters. Never sell a mod
  or lock it behind a paywall. Reselling other people's mods, or leaking a mod
  its creator has not released yet, is treated as piracy in this community.
</Callout>

- **Paid outfits stay paid.** Each outfit in Zenless Zone Zero is its own model with its own hashes. Never put a paid outfit, or part of one, over its free version.
- **No leaked content.** Never use models or textures from versions that are not out yet.
- **Cosmetic only.** A mod changes how things look. Anything that gives an unfair advantage, such as HP numbers or enemy information on screen, has no place in a mod you share. The HP library is for one thing only: changing your agent's look when their HP is low.

## Zip it

1. Right-click the mod's top folder and make a `.zip` or `.7z` with your archive tool.
2. Do not set a password. Players and download scanners must be able to open it.
3. Check that the archive holds the top folder, not loose files.
4. Ship variants, such as other colors or larger textures, as separate archives with clear names.
5. If the archive gets very large, split it into parts and say in the readme what each part holds.

## Test the archive

Test the file you will share, not the folder on your disk.

1. Move your working copy of the mod out of `Mods`, and turn off every other mod for that agent.
2. In XXMI Launcher, open the settings, go to the **ZZMI** tab and untick **Mute Warnings**, so errors show in game.
3. Extract the archive into `%AppData%\XXMI Launcher\ZZMI\Mods`, as a player would. The path should read `Mods\EllenMod\Ellen.ini`, with your own names.
4. Start the game from XXMI Launcher, switch agents, and press `F10`.
5. Check the mod in the agent screen and in motion. Press every key from your readme.
6. Look for error text or an orange `Possible Mod Conflict` warning.

[Test and reload your mod](/docs/zenless-zone-zero/basics/test-your-mod) explains what each warning means.
