<LevelPill level="beginner" />

A Zenless Zone Zero mod never changes the game's files. It swaps what the game draws, while the game runs. This page explains how that works, so most "my mod does nothing" problems make sense before you meet them.

<Accordions>
<Accordion title="Coming from another game?">

**From Genshin Impact or Honkai: Star Rail.** Same XXMI DLL, same launcher, same hotkeys, same Blender add-on (XXMI Tools). What changes in Zenless Zone Zero:

- Set **Character Quality** to **High** and **High-Precision Character Animation** to **Disable** in the game's graphics settings. The game must run in DirectX 11.
- Part textures bind through SlotFix: `Resource\ZZMI\...` lines plus `run = CommandList\ZZMI\SetTextures`. SlotFix ships inside ZZMI. There is no ORFix or NNFix here.
- The mesh follows the **Blend** hash, not the Position hash. Parts match on `match_first_index` and `match_index_count`.
- Many mods need RabbitFX, a separate library you keep exactly once in `Mods`.

**From Wuthering Waves.** Zenless Zone Zero uses XXMI Tools, not WWMI Tools, and has no merged skeleton. Parts are matched by their index buffer hash plus `match_first_index` and `match_index_count`, not by a VB0 hash. The on-screen flag is `$active`, not `$object_detected`.

**From Deadlock or League of Legends.** Nothing is packed or replaced on disk. XXMI swaps data while the game draws, and `F10` reloads your mod in game.

Other game sections: [Genshin Impact](/docs/genshin-impact), [Honkai: Star Rail](/docs/honkai-star-rail), [Wuthering Waves](/docs/wuthering-waves).

</Accordion>

## Mods change what the game draws

Zenless Zone Zero is a Unity game. Mods need it to draw through DirectX 11. Every frame, the game sends thousands of **draw calls** to the graphics card. Each one says: draw these triangles, with these vertices, these textures and these shaders.

Since version 3.0, the game can also run in DirectX 12. ZZMI does not work there, so keep the game in DirectX 11. [Install mods with XXMI Launcher](/docs/zenless-zone-zero/getting-started/install-with-xxmi-launcher) shows the setting.

The XXMI DLL sits between the game and DirectX. It is a file named `d3d11.dll`, built from the 3DMigoto project. XXMI Launcher loads it into the game when you press **Start**. The game thinks it is talking to DirectX. The DLL passes every call on, but first it checks whether a mod wants to change that draw.

<img
  src="/wiki-images/zenless-zone-zero-basics-how-mods-work-1.webp"
  alt="Zenless Zone Zero asks DirectX 11 to draw a mesh, the XXMI DLL hashes it and checks the Mods folder, a matching mod swaps in its own buffers and textures, and the GPU draws the result"
/>

**ZZMI** (Zenless Zone Model Importer) is the Zenless Zone Zero part of XXMI. It is a folder with a main config file (`d3dx.ini`), a `Core\ZZMI` folder of shared files and libraries, and a `ShaderFixes` folder. XXMI Launcher installs and updates ZZMI for you. This page is written for XXMI Launcher 2.5.0, XXMI DLL 1.3.2 and ZZMI 1.5.2.

When ZZMI loads, the game shows this text in the lower-left corner for about 30 seconds:

```text
ZZMI 1.5.2 (PRESS F12 TO SHOW GUIDE)
```

No text means the DLL did not load, so no mod can work.

## What ships inside ZZMI

ZZMI brings its own libraries. Mods call them, and you never install them yourself.

| Library                         | What it does                                                                                                                                                         |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| SlotFix                         | Puts a mod's textures in the right slots for each way the game draws a part: color, outline, face, NPC, Bangboo and world objects. Guides call it "SetTextures" too. |
| TTLib                           | Draws see-through and half see-through parts.                                                                                                                        |
| HP library                      | Lets a mod change a look when your HP is low.                                                                                                                        |
| `FlatNormalMap`, `EmptyGlowMap` | Blank textures a mod can point a slot at, for example to hide a glow.                                                                                                |

**RabbitFX** is different. It is a separate glow and texture library by caverabbit, and many mods need it. You add it to `Mods` yourself, and exactly one copy may exist in the whole `Mods` folder. Two copies crash the game.

## Hashes: how a mod finds its target

XXMI gives every buffer, texture and shader a **hash**: a short code computed from its data. A mod says "when you see this hash, use my files instead".

| Hash of            | Length        | What it is                                                                        |
| ------------------ | ------------- | --------------------------------------------------------------------------------- |
| Index buffer (IB)  | 8 hex digits  | The triangle list of a mesh. One IB often holds several parts, like body A and B. |
| Vertex buffer (VB) | 8 hex digits  | Vertex data: positions, bone weights, UVs, vertex colors.                         |
| Texture            | 8 hex digits  | One image, like a diffuse or light map.                                           |
| Shader             | 16 hex digits | One small GPU program.                                                            |

In a mod's `.ini` file, a texture swap for one part looks like this. `1a2b3c4d` stands for a real IB hash:

```ini
[TextureOverrideEllenBodyA]
hash = 1a2b3c4d
match_first_index = 0
if 0 == 1
    run = CommandListSkinTexture
endif
Resource\ZZMI\Diffuse = ref ResourceEllenBodyADiffuse
run = CommandList\ZZMI\SetTextures

[ResourceEllenBodyADiffuse]
filename = EllenBodyADiffuse.dds
```

The mod hooks the part's index buffer, hands its texture to SlotFix, and SlotFix places it. The `if 0 == 1` block never runs. It stops old fix tools from adding a line there that flattens normal maps. A character mod exported from Blender has more sections, one per buffer and per part. [How a mod .ini works](/docs/zenless-zone-zero/ini/how-a-mod-ini-works) goes through every line.

Four things follow from hashes:

- **A part is found by its IB hash plus its first index and index count.** Body A and Body B often share one index buffer. The `match_first_index` and `match_index_count` lines tell them apart.
- **The mesh follows the Blend hash.** Some agents share a Position hash. A mod that hooks the Position hash also shows on the other agent, which is why the exporter uses the Blend hash.
- **Each outfit is its own model.** An outfit has its own hashes. A mod for an agent's default look does not change the outfit, and the other way round.
- **Textures have two sizes.** On graphics cards with less than 6 GB of video memory, the game uses 1K textures with other hashes. SlotFix does not use texture hashes, so it works on both.

## How ZZMI finds your mods

Mods go in this folder:

```text
%AppData%\XXMI Launcher\ZZMI\Mods
```

ZZMI's `d3dx.ini` tells the DLL what to read:

```ini
[Include]
include = Core\ZZMI\main.ini
include_recursive = Mods
exclude_recursive = DISABLED*
exclude_recursive = desktop.ini
```

What that means for you:

- Every `.ini` file anywhere under `Mods` loads, at any folder depth.
- A file or folder whose name **starts** with `DISABLED` is skipped, with everything inside it. `DISABLED_Hat` is skipped. `Hat_DISABLED` still loads.
- Inside each folder, `.ini` files load first in A to Z order, then the subfolders.
- A mod finds its `.buf`, `.ib` and `.dds` files by the names written in its `.ini`, starting from the `.ini`'s own folder. Rename one file and that part breaks.
- Each `.ini` gets its own namespace. Two mods can use the same section names without clashing.

## One mod per agent

Two mods for the same agent or outfit both match the same hashes. Both run, and the result is a mess. Keep one mod per agent or outfit turned on, and rename the others so they start with `DISABLED`.

When warnings are on, a clash shows orange text like this:

```text
Possible Mod Conflict: Duplicate TextureOverride hash=...
```

XXMI Launcher mutes warnings by default. Turn them on in its settings while you test your mod.

Want several outfits for one agent? [Combine mods into one merged mod](/docs/zenless-zone-zero/ini/merged-mods) and switch between them with a key.

| File            | What it does                                                                                                                   |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `.ini`          | The mod's instructions: which hashes to watch and what to swap in. Plain text, save it as UTF-8.                               |
| `.buf`          | Vertex data. `Position` holds shape, normals and tangents, `Blend` holds bone weights, `Texcoord` holds vertex colors and UVs. |
| `.ib`           | Index buffer: the triangle list of one part.                                                                                   |
| `.dds`          | Textures: diffuse (color), normal map, light map, material map, and sometimes glow maps.                                       |
| `.hlsl`         | Shader code. Only effect mods have it.                                                                                         |
| `hash.json`     | In a frame dump or asset folder. Lists each component and its hashes. XXMI Tools reads it when you export.                     |
| `d3dx_user.ini` | In the `ZZMI` folder, not in a mod. Saves toggle settings. Never edit it by hand.                                              |
| `ShaderFixes`   | A folder in `ZZMI`, not in a mod. ZZMI ships its own files there.                                                              |

## What a mod must never contain

<Callout type="warning" title="Keep these out of every mod">
  XXMI Launcher refuses to start the game if a mod ships `d3dx.ini`. It shows
  `Cannot start with d3dx.ini in Mods folder!`
</Callout>

- **Loader files:** `d3dx.ini`, `d3d11.dll`, or a `ShaderFixes` folder. Package a shader edit as a normal mod instead.
- **Library copies:** SlotFix, TTLib and the HP library ship inside ZZMI, in `ZZMI\Core\ZZMI\Libraries`. Never put a copy in a mod. RabbitFX lives once in `Mods`, never inside another mod's folder. When XXMI Launcher finds a copy of a built-in library in `Mods`, it offers to turn the copy off. Say yes.
- **Programs:** a mod holds `.ini`, `.buf`, `.ib`, `.dds` and sometimes `.hlsl` files. An `.exe` or `.dll` in a skin mod is a warning sign.

## Why updates break mods

Zenless Zone Zero updates about every six weeks. An update can break mods in six ways:

1. **New hashes.** The game re-exports a model or texture, so its hash changes. The mod no longer matches and the agent looks normal. Version 3.3 changed a few hashes, for example the Blend hashes of the `SunnaKfc` outfit.
2. **New buffer layout.** The game changes how vertex data or bone numbers are stored. Version 3.2 changed the bone numbers and the UV format of some meshes and the face data: legs bend, textures scramble, faces show black patches.
3. **Split or remade parts.** Version 2.5 split Jane's `Hair` into `Hair` and `Arms`. Version 3.0 remade Belle. Mods for those parts need a new export from Blender.
4. **Texture changes.** Version 1.3 stopped normal maps from being replaced by hash. Texture hashes also change often. SlotFix avoids most of this, which is why new mods use it.
5. **Importer updates.** ZZMI updates SlotFix for everyone. Once in a while a ZZMI update breaks mods itself, and a fix follows in a few days: ZZMI 1.4.6 and 1.4.7 broke most SlotFix mods, and 1.4.8 and 1.4.9 fixed them. Restarting XXMI Launcher gets the fix.
6. **New graphics settings.** Version 1.3 added High-Precision Character Animation, and version 3.0 added DirectX 12 mode. Both must be off, or mods break.

XXMI Launcher updates ZZMI and its libraries by itself, which fixes library breaks. New hashes and new layouts need a fix tool or an update from the mod's creator. No importer rewrites a mod's hashes for you. The original models in the asset repo are dumps from version 3.2. For 3.3, the ZZZ Mod Fixer v2.3.0 updates the changed hashes. [Fix your mods after a game update](/docs/zenless-zone-zero/getting-started/fix-mods-after-an-update) walks through it.
